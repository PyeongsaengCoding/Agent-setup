# Read-model performance and safety

Use for slow projections, snapshots or graph read paths. Inspect the actual reader, writers and authorization contract before changing them.

1. Separate data availability, live access validation, storage I/O, computation and delivery. Reproduce the exact slow read first and measure real operations and latency before broad code exploration. For maximum-cost-reduction requests, identify the smallest necessary disclosure decision and rank repeated body reads, integrity work and authority discovery for removal; give a concrete reader/writer design rather than stopping at a statement that security checks are necessary.
2. Distinguish the diagnostic identity, serving identity and end-user authority. A tool connection or one successful metadata read does not prove access to the target data. Do not bypass application authorization to diagnose a denial.
3. Keep immutable content integrity separate from fresh disclosure checks. Reproduce revocation, deletion and cancellation during a read; stable-data tests do not prove safe memoization. Private storage readers must cap bytes before or while downloading; wrapping a whole-object read and checking length afterwards does not bound I/O.
   - Strip private bindings (storage paths, internal job/call ids) from the copy serialized to a model provider or public response, and keep them on the stored row that revalidation needs. Prove it by serializing every captured outbound request in the test.
   - When a later stage narrows an offset-pinned excerpt, re-anchor the sub-span to absolute offsets and reject an absent or repeated span; first-match can bind the wrong passage.
   - Pass the exact validated body, manifest and version from integrity checking into response assembly; re-reading the same bytes spends I/O without adding a fresh access observation. Cache immutable material separately from permission decisions and recheck the relevant current state before disclosure or new model transmission.
   - Scope original opening to the server-bound selected citation. Preserve any required whole-answer visibility decision through its authority dependencies, while excluding unrelated body assembly; surrounding citation count should not inflate selected-original body reads.
4. Treat consecutive validation reads as distinct observations until tested. An external actor can revoke or replace a document between reads even when the caller performs no intervening I/O. Reuse only the validated document/version and prove revocation, replacement and final-disclosure fences before eliminating the later read.
   - Exercise mutations exactly between generic saved-answer validation and provider-specific validation for history, completed-turn output and model reuse. A later original-source fence covers only callers that actually reach it. Removing the second pass can expose revoked membership or superseded frozen bindings; retaining only the late pass also needs a transient invalid-then-restored control because early denial can be sticky. Run the candidate with real authority fixtures before accepting static equivalence claims. Use [temporal validation composition](references/temporal-validation.md) for the mutation matrix and candidate decision gate.
5. Verify that numeric storage collectors are active in the actual request and copied into its existing worker/auth contexts. Distinguish fixture operation counts, SDK-observed duration, reported RU and pure network RTT. Mark snapshots with in-flight callbacks incomplete; classify nested spans as subsets so costs and times are not double-counted.
   - Track each supervisor callback separately when one request performs sequential authentication and source reads. Reset timing/state per callback and retain pending/completed counts; reproduce auth completion followed by a gated running source callback before trusting `metrics_complete`. Record callback completion separately from actual thread idleness and permit release.
   - Report the measured serving location and reference fan-out with real SDK counts. Whole-request counts can exceed a fixture because authentication and full-answer reference validation add observations; establish canonical reference equality and temporal authorization semantics before deduplicating them.
   - Count stored references directly with payload-free counters and preserve every frozen-binding field in exact-equality comparisons. The same references may be validated by a generic public-message path and a provider-specific path; callback or validation counts alone cannot establish the number of stored references. A shared source identity never proves identical frozen-input/excerpt bindings.
6. Bound service-wide concurrency, retained results, admission and memory. Test fairness, input-order failure selection, cancellation and capacity losers.
   - Label shared-process tests by the identity actually exercised: separate application/store owners with one hardcoded actor prove application shutdown isolation. Build distinct actor/workspace bindings through domain writers in one shared store before testing cross-user authorization; separate stores can hide lookup-isolation defects. Assert valid own-source controls, cross-owner and cross-workspace refusals, active non-owner membership, mismatched conversation/turn bindings, and synthetic principal/route-owner disagreement. Give each source a unique body marker and storage binding; require denied requests to return no source marker and invoke no Blob reader. Gate concurrent own reads and assert each callback's source binding and budget identity, followed by zero retained work, borrowed permits and waiters.
   - Report fixture authentication and real provider admission as separate evidence. Count a supplied login that matches the existing approved account as one identity. Require valid own-source controls for both Workspaces before calling a denial cross-Workspace isolation; an absent Workspace exercises unknown-Workspace refusal. Keep genuine additional-account coverage open while continuing independent approved recovery, runtime and usage gates.
   - Snapshot cancellation state at the intended observation boundary. A successful HTTP response followed by Connection: close can mark the retained budget cancelled after callback completion; inspecting its later mutable state can falsely report cross-owner cancellation. Count callbacks across every recovery phase and keep fixture failures separate from product defects.
   - Resolve the running event loop before reserving capacity. Guard worker-task construction separately from running work: if construction fails before dispatch, close the unused coroutine, return only that admission's permit, remove its ownership record and rethrow the original exception. Keep running callbacks owned until actual pool completion; early release allows more work than the limiter permits.
   - Verify rollback with the real limiter, an injected constructor failure, a separately gated running callback and a successful admission after rollback. Assert token counts, ownership, exception identity and absence of unawaited-coroutine warnings; distinguish injected-boundary coverage from observed production failure. Use [worker admission and rollback](references/worker-admission.md) for the test sequence.
7. Process projection changes idempotently. Preserve restrictive visibility fences before asynchronous updates; do not serve partially assembled snapshots.
   - Before replacing repeated authority traversal with compact epochs or state vectors, inventory every membership, serving, grant, deletion, retention and audience writer. Activate the shortcut only for domains whose restrictive changes synchronously advance the reader's state before asynchronous cleanup; a missed writer leaves cached disclosure authority stale. Keep epochs monotonic through restoration and reissue, and validate the same dependency vector before and after the read.
8. Test the exact candidate and serving revision. Do not log credentials or private source contents. Distinguish synthetic benchmarks, real-storage checks and authenticated user flows. A test named for a condition (expired deadline, revoked access) must actually set that condition and assert the precondition; passing because the code ignores the field proves nothing.
   - Inspect assertions before adopting a probe's passing count as a safety verdict. A test that prints leaked tokens or lingering tasks can pass while documenting a defect. Report reproduced failure, corrected behavior and residual boundary separately; classify low-memory and monkeypatched failures by reachability evidence rather than calling them impossible.
9. Verify real open, refresh and reentry before reporting recovery. Record remaining latency or permission gaps rather than calling tests a fix.
10. When the full suite fails in files another dirty lane changed, preserve that work and isolate in-process: load the reviewed modules from the Git base through a `sys.meta_path` finder fed by `git show HEAD:<path>`, and separately monkeypatch the suspected parallel reader to a serial loop. Same failure with base modules, green when serial, means the failure is an ordering assumption in the other lane. Record these as diagnostics with exact counts, never as a fix or a full-suite pass, and confirm after your fixes that no failure appears outside that file.

Use the target project's tools and fixtures.
