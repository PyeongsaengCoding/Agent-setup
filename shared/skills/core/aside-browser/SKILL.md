# Aside 브라우저 조작

브라우저 작업은 Aside에서 한다. 에이전트가 동작을 정하고 `aside repl`(또는 `repl` 도구만 노출한 Aside MCP)로 JavaScript를 실행해 직접 조작한다. Aside 자체 AI(`aside exec`, 자연어 `aside` 명령, 에이전트 위임 도구)는 사용하지 않는다. `repl`이 실패하면 연결·프로필·호출 코드를 진단해 `repl`로 복구하고, 다른 브라우저나 자체 AI로 바꾸지 않는다.

## 시작

1. `aside guide repl`과 `aside --help`로 설치된 버전의 REPL 함수를 확인한다. 예전 예시보다 현재 도움말을 따른다.
2. `aside account list`로 계정을 확인한다. CLI 계정과 브라우저 프로필은 서로 다른 목록이다.
3. 프로젝트 지침이 지정한 Aside 프로필을 사용한다. 지정이 없고 작업에 로그인이 필요하면 프로필을 사용자에게 확인한다. 이름이 비슷한 다른 프로필로 대신하지 않는다.

## 조작

- 기본 흐름: `openTab(url)` 또는 `listBrowserTabs()`·`attachBrowserTab()` → `snapshot()`으로 상태 읽기 → 클릭·입력 → 다시 읽어 결과 확인.
- 서로 의존하는 동작은 한 번의 `aside repl` 실행 안에 둔다. 한 번 실행한 REPL의 변수와 탭은 다음 실행에서 유지된다고 가정하지 않고, 필요하면 탭을 다시 찾는다.
- 프로세스 종료 코드 0만으로 성공을 판단하지 않는다. 출력에 `[error]`가 있는지 보고, 동작 결과를 다시 읽거나 성공 표시 문자열을 출력해 확인한다.
- 화면 캡처를 파일로 저장했다면 실제 이미지 파일인지 확인한 뒤 보고한다.
- 탭을 만든 사실과 사용자가 그 탭을 화면에서 보는 사실은 별개다. 확인하지 않았다면 "보실 수 있다"고 말하지 않는다.

## 계정과 데이터

- 계정이 걸린 변경(게시, 결제, 설정 변경, 삭제) 전에는 해당 서비스의 계정 메뉴에서 실제 이메일을 확인한다. 프로필 이름으로 계정을 추정하지 않는다.
- 비밀번호·인증 코드·복구 키는 사용자가 직접 입력한다. 로그인 화면 snapshot을 출력할 때 비밀번호 칸 값은 지우고, REPL 변수에 남은 인증 링크·토큰은 사용 후 비운다.
- 쿠키·비밀번호 DB·계정 파일 내용을 출력하거나 파일로 저장하지 않는다.
- 같은 사이트 자원을 여러 작업이 동시에 수정하지 않는다.
