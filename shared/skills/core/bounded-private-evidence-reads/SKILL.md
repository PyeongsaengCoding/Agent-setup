# Bounded private evidence reads

## When to use
Use when existing consumers accept a private-byte callback but production composition has not supplied it, when a whole-object storage adapter must gain an I/O cap, when an authorized upload corpus must be inspected completely and reconciled against its processing results, or when real private sources must exercise an isolated local application.

## Real-source local QA gates

- For production-parity QA, inherit the deployed product's effective collection scope, pagination, attachment handling, retries, timeouts, size limits and provider configuration. Agent-invented per-run body or call quotas can stop a valid workflow and require their own explicit coverage justification. Isolate authorized writes by exact QA targets while retaining real provider composition; confirm external write targets and private-data retention before execution.

- Prepare account admission, the selected source, actual product components and the final reload/readback path before model execution; keep the RAM store alive until those checks finish, because shutdown discards private answers that cannot be recovered from hashes.
- Record authentication stages separately: provider login, genuine bearer acceptance, selected Workspace role, local proxy admission and the product's own signature/membership checks each prove their own boundary. An account designated as Reviewer can hold Owner in its personal Workspace; use the currently verified role.
- Resolve credential references and reconcile cached settings before constructing credential runtimes or creating QA cloud targets. Test import-before-secret-resolution against the actual runtime. Classify missing or stale QA configuration separately from provider authorization failures; base reconnection advice on an observed provider response. Preserve existing grants during configuration repair.
- Seed approved source snapshots through the product's normal record-saving path, preserve their successful-sync timestamp and source bindings, and verify original-body hash, source-state token, excerpt containment and citation markers before claiming a grounded answer.
- Test automatic source discovery with a natural question that omits the literal source-type keyword; explicitly naming mail can pass retrieval while leaving semantic discovery untested. Preserve real freshness metadata and observe the model-selected branch.
- Distinguish stored-source continuation, real provider acquisition, search readiness and downstream enrichment. A folder or message-id page establishes only its observed inventory stage. Trace the concrete readiness predicate before diagnosing an enrichment dependency: source-level semantic extraction required for common search and a deferred workspace graph are separate stages.
- Plan a complete QA run from identity admission through acquisition, projection, answer generation and UI reload. Use product collection and processing settings for production-parity runs. Apply sample ceilings only to explicitly scoped sample tests and report their partial coverage. Bind account, date window, external-write targets and retention to the person's approved scope.
- Make long-running real QA runners self-terminating. Treat product states that wait on a person (for example a turn parked for a mail-sync/stored-mail choice with a far-future next attempt, or a consent marked failed) as terminal: record the state and exit with a receipt, since the product will never advance it on its own. Add a stall detector keyed on an unchanged state signature (turn status/stage, work-item counts, model-call count) instead of an artificial work cap. Persist safe failure categories and stages of failed work items to the progress file while running, because killing a stuck run discards the RAM state needed to diagnose it.
- When a parent checks on a delegated QA run, read the progress sample's state signature and elapsed time rather than the process's liveness; a live process with an unchanged parked stage is stuck, not working.
- Preserve private originals, subjects, tokens and derived answers in process memory when retention is restricted. Save allowlisted status, hashes and source-check booleans; redact private regions before recording screenshots without changing their measured layout.
- Separate exact API answer hashes from rendered-text comparisons and product-component checks. A reload of a diagnostic page proves that page's API re-read; record actual product rendering and complete sign-in separately. Record semantic completion and addressed/required counts independently of transport completion, citations and stable reload hashes, because a correctly saved and rendered answer can still satisfy only part of the question.

Follow [authenticated local QA](references/authenticated-local-qa.md) for the ordered recipe.

## Procedure
1. Read and search the source to trace every callback consumer and its API/worker composition root. Inspect existing private storage settings and process-scoped client construction; reuse them before introducing settings or infrastructure.
2. Define the callback as `read(name, *, max_bytes) -> bytes`. Match canonical deterministic object names exactly before storage access. Keep absent configuration as a missing dependency and preserve the consumer's safe refusal.
3. Write behavioral RED tests through real HTTP handlers, application execution, and native tool composition. Mock external provider/network boundaries only; use actual local files and existing store fixtures.
4. Bound Local reads before and during I/O: resolve and check the configured root, reject namespace redirection, stat a regular file, recheck descriptor size, and use an unbuffered read with an explicit positive cap. Refuse size changes and errors. If concurrent filesystem mutation is in scope, use descriptor-relative no-follow opens for each component.
5. Bound Azure reads using object properties followed by a range whose length is positive and no greater than the cap. Bind the range to the properties ETag; return empty bytes directly for an empty object so zero range length cannot accidentally mean a whole-object download. Test properties, range arguments, truncation, excess bytes, and errors with an injected offline service client.
6. Reuse the same process-scoped adapter across API and worker consumers. Pass the reader through existing typed dependencies and source recorders without importing the composition root into services.
7. Run GREEN on connected paths, then adjacent tests, changed-file lint, architecture gates, diff hygiene, and the requested full suite. Record exact counts and full SHA256 hashes from actual shell or script output.

## Authenticated producer and immutable writer extension
- Bind signed host requests/results to a version, direction, opaque job identity, request hash, fence, generation, lease and original deadline. Admit only exact requested/applied conditions and a bounded hash-checked body; provenance authentication does not establish page truth.
- Require transport, verifier and private storage before enabling dispatch. Keep missing dependencies quiet and prove zero discovery scans through the composed worker.
- Journal transport start before external I/O. Treat a lost external result as unknown work instead of observing twice; recover staging/validated phases solely from their immutable stored body and reconcile committed phases read-only.
- Guard current message, turn, membership, Workspace and parent authority at conditional publication. Recheck a controlled clock before and after every I/O boundary, including the final commit read and final authority guard reads. Accept a resampled callable clock; when supporting a fixed historical timestamp, count monotonic elapsed I/O for expiry checks while preserving deterministic recorded timestamps.
- Reserve an explicit bounded postprocessing margin from the original lease/deadline before host dispatch, and recompute after the started journal and final authority reads. Generate/sign/verify the request before marking started. If journal I/O leaves no safe transport budget, record known zero host work under the same owner/fence/context CAS; any expiry-only abandonment exception must be failure-only and refuse a replacement claim. Keep actual lost host responses unknown, and preserve slow storage expiry refusal rather than treating the reserve as a hard I/O guarantee.
- Log only fixed safe category/type labels for dispatch and storage failures. A safe outward writer error may retain a sanitized type property; suppress raw cause rendering and never log exc_info, stack_info, exception messages, bodies, URLs, condition values, identifiers or credentials. Test sentinel secrets in messages and custom class names through caplog.
- Publish local objects with descriptor-relative no-follow opens, an exclusive temporary file and an atomic create-only hard link. Clean temporary failures and accept collisions only after a bounded same-content read. Use Azure overwrite=False, explicit content identity and an ETag-bound collision read.
- Select later authorized work within a bounded fair scan when an earlier Workspace is unavailable; count owned unknown work against the cycle's execution budget. This preserves isolation without widening discovery or repeating paid work.

## Saved source cancellation and SDK transport
- Reserve the actual AnyIO default thread limiter atomically before source callback dispatch; refuse saturation without a queue or an additional executor. Keep the reservation through callback return and AnyIO's idle-worker publication, since releasing from the thread's first completion notification can admit another pool thread too early.
- Supervise the callback independently of the HTTP task. Propagate raw outer task cancellation, cancel the cooperative read token, and retain the actual worker reservation through completion. Join request watchers, deadline timers and shutdown wait children in `finally`, including cancelled shutdown.
- Bind the existing browser reopen deadline to the request scope and preserve its shared retry budget. Activate SDK timeout/retry overrides only for that browser scope; keep ordinary source results and inactive client settings unchanged.
- Install transport guards once at process client composition and check every actual send and streamed chunk. Test the installed SDK's automatic metadata and retry paths: Cosmos-owned refresh threads can lose ContextVars, requiring an explicitly tested per-call budget handoff consumed before the requests transport.
- Preserve the cooperative InterruptedError when stopped socket I/O returns a provider timeout. Check between local open, descriptor metadata and body read as well as between Blob properties and download; a safe eventual refusal alone does not prove later private I/O stopped.
- Keep socket inactivity ceilings distinct from total execution time. Blob short-body retries and Cosmos throttling can remain below pipeline retry controls; prove send counts and retain the worker slot while actual synchronous work continues.
- Give the source route one ASGI receive owner and fence each successful body send. Hold successful headers until the first body is ready so pre-commit expiry returns safe refusal with CORS; recheck immediately before every body send after any awaited header or chunk send. Abort incomplete responses after committed headers instead of emitting another status.
- Exercise the actual production tenant/auth callable and app composition under real default-limiter saturation. Source callbacks can be queue-free while earlier closed-beta or Workspace callbacks still queue; put those source-only callbacks under the same bounded supervisor after bearer verification, preserve ordinary routes, and stop later registry I/O on disconnect.
- Test direct supervisor-task cancellation before its first turn and while its callback has returned but AnyIO idle publication is held. Keep the pool result await alive through publication, release unused pre-dispatch reservations, and prove reuse of the same real worker; request cancellation alone misses both accounting risks.
- Distinguish the ASGI authorization boundary from bytes already passed to the server. Pair controlled-clock send-boundary tests with actual main JSON/content-length abort and a real Uvicorn paused-write/drain test; in-flight authorized bytes may finish after expiry while the next source send must be refused.
- Force focused pytest probes into a unique scratch-directory `--basetemp` and clean it afterward; the host's default pytest temporary root can differ from the runtime's advertised scratch directory.

## Terminal journal maintenance
- Catch a dedicated ValueError-compatible private-reader error only at evidence publication boundaries; use the existing claim attempt cap to finalize unconfirmed evidence, and let unrelated authority, lease, cancellation and logic failures propagate without terminal writes.
- Keep failed publication distinct from transport admission: preserve the started phase, immutable evidence metadata, original deadline, attempt count and fencing instead of relabeling observed work as never started.
- Give orphan abandonment a separate bounded worker phase: point-read the actual journal document, validate its type/pool/tenant/deterministic identity and canonical timestamps, then use a fresh-ETag journal-only failure CAS after the original deadline grace and lease expiry. Keep parent/message/Blob access and retention policy outside this path.
- Compare immutable awaiting checkpoint bindings during CAS retries while allowing the existing bounded poll/hint counters to advance; comparing the whole native state breaks legitimate read-only polling contention.
- Run a secondary bounded maintenance step inside `except Exception:` and finish with a bare `raise`, never `try/finally`: a `finally` that itself raises replaces the primary failure. Log the secondary failure only as a fixed safe type label; test with a sentinel secret in the message and a custom class name that the primary exception identity, `__context__ is None`, and caplog text all hold.
- Pin maintenance read/write budgets as explicit counts in a characterization test (one TOP(scan) query, point reads per scanned candidate plus one readback per successful write, CAS attempts <= scan, successful writes <= limit) with mixed invalid/conflict/authorized candidates; document those counts instead of claiming a single read.
- Check `architecture-baseline.json` line budgets before editing a file sitting exactly at its cap; make the edit line-neutral rather than widening the budget.
- Guard pytest runner entry points with `if __name__ == '__main__'` when the suite uses multiprocessing spawn; otherwise a diagnostic runner can recursively launch the suite in the child and create a false process-death failure.
- When network access is forbidden, preserve the guard and report loopback-dependent fixture tests separately from behavioral failures; do not remove the guard or substitute fabricated provider responses to inflate full-suite results.

## Pitfalls
- Wrapping `read_bytes()` or an unrestricted cloud `readall()` only limits returned data; it does not limit download I/O.
- Buffered local reads can prefetch beyond a small cap; use unbuffered file reads.
- A saved-answer original route and a worker application path can each miss a dependency even when standalone callback consumers pass.
- Preserve unrelated dirty files and distinguish their known failures from regressions in the changed paths.

## Whole-upload evidence audits
1. Establish the selected company/user/upload corpus before fetching content. For high-agreement case selection, rank actual comparison outcomes and record their denominator; extraction success, field counts and OCR confidence measure different things. Report the selected corpus separately from all historical records screened.
2. Bind enumeration to each exact authorized upload namespace and verify its source-upload relationship before listing. Reconcile declared attachments, stored page results and every listed original. For a request covering all evidence, include every type, file, page and sheet in each selected bundle; preserve extra, unclassified and failed documents. Converter support and a fixed per-type sample count must not determine the inspection scope.
3. Acquire originals with the bounded, ETag-bound reader and verify local hashes. For human delivery, organize copies under company/type folders and keep original input, evidence and converted test input distinct. Maintain a used-destination set or per-source manifest: two separate uploads with the same filename and bytes still need separate entries, because a content-equality cache can silently reduce the delivered file count. Suffix collisions deterministically with the source-file identifier, preserve original names in the private mapping, and verify physical destination counts and every hash before reporting the number delivered. Read every sheet/page with a format-appropriate reader. Keep native text, local OCR, stored provider extraction and current consumer conversion as separate observations; extracting text locally does not enable the application's OCR pipeline.
4. Render pages with empty extracted text before classifying them as empty. Check their stored fields as well: blank table continuations can carry a successful processing status without dates or numeric evidence. Record readability and source uncertainty explicitly rather than converting blanks to zero.
5. Exercise every original through the real local consumer and assert one file-status receipt per input. Probe stored-result adapters over the complete entry set and identify silently skipped document types. Keep file, page, extraction-entry, identity-check and compared-field totals separate; a whole-file timeout can represent several absent page results, and identity checks can inflate a field-comparison denominator.
6. Build comparison inputs only from the independent submitted input, with source-cell and hash traces. Leave fields with unverified units, timezones or interval/point meanings unresolved. Hold evidence fixed while changing the input for mismatch, date and identity controls; label controls restricted to identified records as partial identity coverage.
7. Report acquisition, automated readability, conversion support, actual numeric comparison and manual verification separately. Preserve unsupported and zero-comparison outcomes in the company/type matrix. Accepted uploads, stored reports and completed workers establish workflow behavior; compatibility claims require observed comparisons for the named types and fields. When an adapter emits zero records for a document type, close only the completed capability review and keep that type's conversion and numeric-comparison work unresolved; recording the unsupported result does not implement the missing connection.

## Verification
Require observed behavioral RED and GREEN for newly connected consumers. Assert that over-limit properties prevent download, invalid names prevent storage access, missing configuration prevents construction, and unreadable evidence prevents provider invocation or partial-answer delivery. Report local verification separately from cloud execution and deployment.
