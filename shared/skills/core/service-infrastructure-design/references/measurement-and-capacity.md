# Measurement coverage and capacity decisions

Use for infrastructure decisions that must justify latency, capacity or cost claims. This recipe does not authorize live changes.

## 1. Establish collection coverage

For Application Insights-backed systems:

```sh
az monitor app-insights query -g <resource-group> -a <application-insights-name> --analytics-query '<KQL>' -o json
```

Query a bounded union of `requests`, `dependencies`, `traces`, `customEvents` and `customMetrics`, grouped by table and `cloud_RoleName`. Inspect dimension keys and metric names without exporting messages, customer query strings, request bodies or raw dependency URLs.

Treat an empty request table as a collection gap in that resource, not proof no requests occurred. Treat `unknown_service` as an attribution gap; inspect runtime/resource attributes before assigning timings to API or worker. Inspect durable provider receipts and write-failure behavior independently because diagnostic spans do not prove accounting completeness. Establish deployed revision and actual collection with a real execution before upgrading repository capabilities to an operating claim.

## 2. Inspect units and sampling

```kusto
dependencies
| getschema
| where ColumnName in ("duration", "itemCount", "success")
| project ColumnName, DataType
```

Inspect types before duration arithmetic. `dependencies.duration` can already be numeric milliseconds; divide by a timespan only when the actual schema requires it. Adapt field names explicitly for workspace tables rather than assuming equivalent schemas.

Report stored rows and represented `itemCount` volume separately. When appropriate, use `percentilew(duration, itemCount, 50)` and `percentilew(duration, itemCount, 95)`, label estimates as sampling-based, and report actual sample size. Represented volume is not an exact invoice count; a handful of samples does not establish a dependable p95.

## 3. Reconcile one materialized dataset

A fixed event-time cutoff does not freeze ingestion. Compute totals that must agree from one dataset:

```kusto
let End = now();
let D = materialize(
    dependencies
    | where timestamp between (End - 7d .. End)
    | where type == "HTTP"
    | where target contains "documents.azure.com"
);
union
    (D
     | summarize StoredRows=count(), RepresentedCalls=sum(itemCount),
         P50_ms=percentilew(duration, itemCount, 50),
         P95_ms=percentilew(duration, itemCount, 95)
     | extend Kind="latency"),
    (D
     | summarize StoredRows=count(), RepresentedCalls=sum(itemCount) by resultCode
     | extend Kind="status")
```

Parse the returned JSON and validate summed status rows/represented calls against the latency row. Do not choose a convenient total from independently fetched mismatching queries. Classify expected-negative reads and actual error paths before treating every 4xx as a capacity failure.

## 4. Measure actual paths

Label dependency duration client-observed call time, not pure network RTT; it can mix connection/admission, remote processing and SDK behavior. Do not subtract overlapping timings and rename the remainder network latency.

Measure missing links from actual service locations, varying cold/warm connections, representative payload and bounded concurrency. Record p50/p95/p99, sample count, bytes, errors and observation window. Developer-machine-to-cloud measurements are a different path.

Connect stages to execution identity and separate queue/capacity/DB-lock waits, query time, model response start/generation, site navigation/rendering and evidence commit. Compare wall-clock with critical path; summing parallel spans overstates latency.

For a proxied browser baseline, run one declared owned endpoint sequentially from the qualified host: record the first navigation separately from same-browser reloads. Capture monotonic navigation wall time and browser NavigationTiming fields for connect, secure connection, request/response, DOM/load, transferSize, encoded/decoded body size and nextHopProtocol. Use transfer and connection fields to classify cache/reuse before labeling a group warm. Treat transferSize as the browser-reported value, not a packet capture or wire-byte ledger. Browser DNS timing does not expose the proxy's resolver or upstream connection stages. Keep first-navigation, host cold-start and provider cold-start distinct; report small-sample median/range and defer tail-latency or capacity claims until representative samples exist. Stop the exact trial instance and read back any temporary endpoint allowance removal after measurement.

### Lifecycle-budget decision recipe

1. Trace the actual startup, readiness, observation, publication and cleanup calls with source reads. Label every timeout as a ceiling and every observed timing with its sample and execution origin; use a calculator for budget arithmetic. A ceiling exceeding the lease establishes an unqualified worst-case path, not proof that every execution takes that long.
2. Map the original question deadline, worker lease, transport timeout, postprocessing reserve and supervisor lifetime to their clock anchors. Include lock occupancy through cleanup when estimating useful throughput; an API timeout alone does not stop the host workload.
3. Compare the lifecycle choices below, then obtain the decision that changes product or security semantics. Keep the original budget intact while the choice is pending.

| Choice | Contract impact | Required qualification |
|---|---|---|
| Synchronous cold execution | Existing wire can remain intact if measured execution fits | Actual cold readiness plus observation/publication within lease; host stops after caller loss |
| Prepared execution | Preserve backend wire; split host prepare/observe/cleanup | Denied egress while prepared, immutable slot ownership, fresh admission proof, one-job isolation, bounded idle expiry and cleanup |
| Asynchronous acceptance/result collection | Extend durable states and lost-response reconciliation | Authenticated acceptance receipt, fenced result retrieval, restart recovery and no repeated external work |

4. For prepared execution, document whether a slot is consumed by one job or reused. Require explicit cross-job state isolation evidence before reuse, and measure preparation cost and idle occupancy separately from observation latency. Treat injected adapter readiness and synthetic condition results as offline contract tests only.
5. Before host qualification, exercise the composed receiver-to-lifecycle boundary offline. Generate requests with the actual backend contract, verify responses with its actual verifier, and run found, empty and explicit failure outcomes through private storage, question resume and saved-original reading. Inject external engines only at their boundary and label their outputs as test fixtures. Make the adapter own the prepared context until cleanup, bind backend and controller generations explicitly, and convert UTC deadline differences into a bounded monotonic budget without extending the original lease. Run the independently authored suites together; record the single observed count rather than summing overlapping child selections.
6. Qualify the chosen lifecycle on the actual isolated host with natural expiry, forced termination and competing-generation controls. Keep unsupported condition application unverified even when request signatures and host readiness pass.
7. Keep retention decisions independent of lifecycle timing. Until a replay-ledger pruning policy is approved, bound admission by capacity and refuse new work safely rather than deriving deletion permission from an execution grace period. Key replay protection by logical job across changed fences and generations, commit the started marker before engine invocation, and permit another admission only after a durable, definite zero-work refusal within the existing attempt cap. Test simultaneous requests, process termination, database recovery and reopened receiver instances; startup recovery must establish lifetime exclusive ownership before classifying another instance's in-flight work as lost. Store only the hashes and state needed for replay fencing, with private directory/database permissions and no raw grant tokens, URLs or page bodies.

## 5. Check accounting completeness

Reconcile admitted executions, started attempts and terminal or explicitly unfinished receipts. Reconcile committed artifact references with accessible, hash-valid artifacts. Surface receipt-write failures, export drops and unknown usage as operating signals.

Deduplicate intermediate/final updates by attempt identity; connect actual retry attempts to their logical call. Distinguish measured usage, price-derived estimates, allocated shared compute and unknown billing. Idempotent job completion does not establish exactly-once external charges after an interrupted call.

### Bounded-accounting implementation verification

Use this sequence when adding durable execution accounting to an existing inline/worker workflow:

1. **Pin the real caller and eligibility boundary.** Invoke the shared execution function and its ancillary jobs, not only the ledger helper. Test completed input, stale pending input whose saved row is completed, and running work with a valid lease. Remove the optional budget row and reject accounting writes; genuine no-op cases must still return their existing result without provider calls or replacement budget windows. Separate legitimate outbox cleanup from accounting writes rather than asserting that every ancillary job performs zero writes.
2. **Exercise each admission failure separately.** Fail the execution start, budget creation, claim CAS and claimed checkpoint independently. Require no provider transport before mandatory admission succeeds. Fail only the provider's final receipt write in a positive-result control and require that known result to survive. Run a multi-item ancillary-job batch with one failed admission and prove later eligible items continue while the failed item remains retryable.
3. **Preserve persisted budgets under concurrency.** Delay two eligible callers until both have observed an absent budget, then release them together. Use create-only persistence and resolve a creation conflict by adopting the stored deadline and model-call count; do not overwrite the winner or invent a new retry window. Verify existing-budget retries retain the original anchor and increment the saved count. Count budget, receipt and ledger writes by document type and identity, because total storage calls conflate distinct contracts.
4. **Isolate ledger contention from storage contention.** Block aggregate exit persistence with Events before acquiring the test store's global lock. Run a provider attempt in a separately copied Context and require its own completed receipt to appear while the aggregate write remains blocked. Release persistence, join the workers and check publication order, monotonic write sequence, final usage and the configured late-write bound. Repeat with aggregate persistence failure; a globally locking store cannot distinguish ledger-lock contention from ordinary receipt I/O.
5. **Guard helper-level identity and admission, not only connected callers.** On first claim binding, refuse changes to populated identity, the tenant or the normalized schema/ontology versions instead of overwriting them. Allow hydration only of fields that were absent. After the first binding, reject later changes. A deferred ledger whose mandatory start was not persisted must fail closed before provider transport; never write a receipt that references an unwritten ledger row. Classify receipt costs into a ledger subset only when the active inclusive collector is that ledger's own totals, because a nested collector otherwise makes the subset larger than the total that is said to include it. Write negative tests that call the helpers directly: a reviewer can find these gaps even after the connected-caller tests pass. When an existing fixture conflicts with a new guard, make the saved row and the incoming input coherent; do not weaken the guard.
6. **Check bounded publication and cost conservation.** Verify normal checkpoint count, at most the configured late snapshot, bounded attempt retention and no write per ordinary DB operation. Keep aggregate-row persistence outside business totals; classify receipt persistence explicitly as either included usage or separate cost, never both. Assert measured subset counts and RU do not exceed the corresponding inclusive totals within the tested collector. Leave the current snapshot's own write charge unknown because that snapshot precedes its response.
7. **Close at the demonstrated boundary.** Include interrupted-process and copied-thread controls when claiming recovery. Test logs with private canary input and require only generated opaque correlation references plus bounded numeric fields. Report uncheckpointed work, further work after the late-write bound, hidden SDK retries and unmeasured resources as coverage gaps. A blocking-defect-free independent review is not proof of live collection, exact billing or completion of the wider infrastructure plan.

For a Python project, use the manifest-compatible interpreter for each RED and GREEN run, then broaden only to affected callers:

```sh
<project-python> -m pytest <new-regression-file> <adjacent-caller-tests> -q
<project-python> -m ruff check <changed-python-paths>
<project-python> <architecture-check-script>
git diff --check
```

Save each command's exit status independently before running formatting or log-display commands, because a trailing successful command can conceal a failed suite. Record the exact test selection and worktree freshness; different focused selections cannot be added together or compared as identical coverage. Preserve unrelated-owner failures and report the full-suite HOLD separately from the accounting slice's observed results.

## 6. Qualify a risky runtime on the real host

Use after the user approves the cost and change scope. Do not touch production resources.

1. **Isolate the scope.** Create a dedicated resource group with tags covering purpose, `productionData=none` and a review-by date. Declare only the qualification resources in a template: the candidate plan/host, a registry with the admin user and anonymous pull disabled, and a pull-only managed identity. Run `az deployment group validate`, then `what-if` with `--no-pretty-print -o json`. Parse the result and assert that every change is a Create inside the qualification group before applying. Afterwards, read back each resource's SKU/state, its security flags and role assignments scoped to the registry; a resource-group-scoped role listing can omit them.
2. **Price from primary meters.** Query the Retail Prices API, follow every `NextPageLink`, and select the region-specific primary meter by SKU and product, such as the Linux plan rather than a same-named IoT or Windows meter. Compute daily and 730-hour fixed costs with a tool. Store the raw price evidence and list what the estimate excludes.
3. **Use a minimal probe image.** Use the official pinned browser image, run as a non-root user and listen only on fixed `/health` and `/report` endpoints. Make no arbitrary URL or command inputs and use only data URLs. Launch with the sandbox enabled and never use `--no-sandbox`. Report only sanitized booleans, numbers and failure categories, with no env values, identifiers or raw stderr. Report credential and egress isolation as unknown until enforcement is actually tested. The overall verdict must fail closed. Build the image remotely in the registry and deploy it to a separate app.
4. **Capture live renderer facts.** Snapshot each renderer's seccomp, NoNewPrivs and namespace facts before closing Chromium, then evaluate those snapshots. Include PID 1 as a valid ancestry target in containers. Exercise the actual Playwright-check callback's process lifetime in tests; injected prebuilt facts alone can miss shutdown and discovery bugs. Require every observed renderer to be readable before passing; a zero count or unreadable subset remains unknown and needs bounded numeric discovery diagnostics. Chromium zygote children can rewrite `/proc/<pid>/cmdline` into one space-joined NUL field, so recognize renderer flags in both real argv and rewritten titles. Test the production discovery callback with a fake Playwright lifecycle that creates processes on launch and removes them on close, then repeat on the actual host. Report direct namespace evidence separately from any inferred PID-namespace fallback and retain the inference's prerequisites.
5. **Test image-pull identity exposure.** A private-registry pull identity attached to an App Service app can also expose identity endpoint/header variables inside its workload. Restrict its role to the qualification registry and report variable presence only. Credential isolation requires a bounded negative token-eligibility test without retaining token response bodies; variable presence alone does not prove token access. Container Apps `identitySettings.lifecycle=None` can persist successfully while those variables remain present. A reduced child environment and request-routing abort hooks alone do not enforce process or network credential isolation. Qualify each host/profile separately: an ordinary Container Apps Consumption candidate can block user namespace creation and sandboxed Chromium even when App Service passes; this does not establish the behavior of dedicated sandbox/session products.
6. **Measure from the host.** Collect cold and warm timings, sandbox/user-namespace facts and dependency latency from inside the deployed host. Distinguish developer-to-app HTTP observations from cloud service-to-service latency. Pin deployments to the built digest, read the configuration back, and explicitly restart the test app when a configuration update still serves the previous process's report. Report the cleanup or retention decision together with the cost that continues to accrue; Stopping a webapp leaves allocated plan billing active. For a rejected candidate, delete the app and environment, verify the managed LB/IP resource group is absent, then confirm an exact environment GET returns ResourceNotFound. A `ScheduledForDelete` state or a successful wait command alone is incomplete cleanup evidence. Reconcile actual managed LB/IP counts with the prepared estimate before reporting recurring cost; external ACA qualification can create one public IP rather than the initially assumed two.

### Linux VM qualification follow-up

1. **Freeze the revision and stop untrusted work.** Verify local and remote bootstrap/profile hashes, stop the probe and read back the running-container list before changing trust boundaries. Keep the initial installation hash and the reviewed runtime hash distinct. Reapplying a bootstrap template can reattach a deliberately detached pull identity; use scoped runtime changes and preserve unrelated policy.
2. **Build firewall replacement tests before applying.** Execute the real shell entry point with isolated command stubs. Model live rules separately from a staged restore transaction; inject parser/commit failures and test concurrent rebuild/start and bounded lock failure. Preserve legacy deny and unrelated shared-chain rules. Serialize bootstrap mutations with a bounded advisory lock, close its descriptor for the workload launcher, and rebuild only a dedicated owned chain using `iptables-restore --noflush --wait 5` with one COMMIT and a fail-closed guard. Never flush the live shared chain: appending a DROP after a flush still leaves a packet window. Check goto/jump RETURN behavior against preserved rules before enabling web traffic. Test host INPUT with no owned rules, ACCEPT only, DROP only, both rules, and reversed order; rebuild the owned ESTABLISHED/RELATED ACCEPT above the bridge DROP in the same COMMIT while preserving unrelated rules. A DROP inserted above an existing ACCEPT interrupts host-initiated reply traffic. Write the applied-mode/address snapshot only after successful COMMIT, preserve its previous contents on failure, and reapply or compare the current configured mode before running verification; rule presence alone cannot detect a stale public-web allowance.
3. **Keep transaction input free of diagnostic output.** Redirect both stdout and stderr from rule-existence checks inside the restore-file generation block, for example `iptables -w 5 -C INPUT ... >/dev/null 2>&1`. Successful checks on a real nft-backed host can print rule descriptions; stderr-only suppression lets those descriptions corrupt the restore input. Make the stub emit stdout on successful checks and require a clean, parseable transaction. Capture each command's exit status before printing hashes or rules, because successful readback commands can mask a failed apply.
4. **Separate trusted pull from runtime identity checks.** AzurePlatformIMDS supports the platform Deny control; keep metadata available during trusted provisioning/pull, erase credential caches, detach the exact pull identity, and read back its removal before restoring the runtime Deny. In the bounded Azure IMDS flow, accept the verified detached response pair (`400/400`) directly, reject token success and unexpected responses, and label `000/000` unreachable. For an unreachable route, require a fresh externally collected exact `az vm show --ids <target> --output json` identity-null readback. Bind the root-owned 0600, single-link, bounded-size evidence to the target VM, image reference/ID, pull session and current bootstrap hash; enforce freshness and consume it once per admission. Invalidate it before reattachment, repull or reinstall. Bootstrap must never generate its own control-plane assertion, and token response bodies must be discarded.
5. **Pin runtime addresses and sandbox policy.** Supply and validate the host's own public IPv4 explicitly after deployment; metadata becomes unavailable after runtime Deny and must never silently remove the own-IP DROP. Qualify the exact capability/seccomp/AppArmor combination. With cap-drop ALL, Docker's capability-conditioned chroot allowance can deny Chromium's namespace sandbox even when user namespace creation works. Reproduce the exact failure, test a narrow syscall allowance while retaining kernel capability checks and zero outer capabilities, then require live renderer namespace/seccomp/NoNewPrivs evidence. Keep the upstream Playwright namespace rule intact and pin the composed profile hash.
6. **Exercise real Linux behavior, then paired network controls.** Apply and read back the owned chain, repeat replacement and exercise concurrent commands. Collect enforcement counters from the active owned chain, not preserved legacy chains; compare before/after snapshots without a rebuild between them, because replacement resets counters. Pair every claimed blocked destination/port with a reachable positive control at that exact endpoint or a matching DROP delta. An absent listener remains INCONCLUSIVE. Test default-all-deny and web-enabled modes separately; for allowed HTTPS verify DNS matches the declared owned IP and the TLS handshake succeeds while private/platform controls still fail.
7. **Close the remaining acceptance gates explicitly.** Observe Docker's resolver path and define its permitted destinations; host-mediated DNS can escape source-subnet forwarding rules. On an owned qualification host, start a bounded `tcpdump -i <uplink> -n -q -l udp port 53` capture, consume diagnostic lines until the actual `listening on` readiness message, flush the trusted resolver cache if authorized, then resolve one declared owned hostname inside the container. Record only source/destination packet headers and returned addresses. A host-source packet to the platform resolver identifies a separate trusted DNS path; forwarded-container port 53 DROP rules do not govern that path. Keep hostname permissions and possible DNS-over-HTTPS over allowed port 443 separate from private-IP enforcement. Retain DNS rebinding, redirects, IPv6, host-local versus container-loopback and own-public-IP live-fixture checks as separate gates. Run continuous forbidden-destination traffic during policy replacement before claiming there is no open window; concurrent command success alone proves only command execution. Use an explicitly owned live external endpoint and a platform-negative endpoint, count attempts and successful connections over a fixed monotonic window, and exercise repeated replacements while the non-root probe runs. Report zero observed successes as a finite sample rather than universal packet-level proof. Read `/proc/net/if_inet6` and the relevant IPv6 sysctls inside the container to distinguish external IPv6 interfaces from local loopback. Attribute forwarding warnings by network namespace and read back the host's `net.ipv4.ip_forward` before assigning a cause to failed connections. Configure transient-unit post-stop container removal and test actual lifetime expiry with a short bound, capture the unit's runtime-limit journal event, read back `docker ps -a` absence, and require a new identity assertion for the next start. A configured ExecStopPost or successful manual stop does not establish expiry cleanup. Restore the safe mode and verify stopped workloads after each bounded trial; preserve native unknown/FAIL gates until their own acceptance evidence exists.

### Representation-safe runtime readback

Use when an offline-tested security validator rejects the actual host. Diagnose one boundary at a time while retaining the existing enforcement and deadlines.

1. **Locate the exact refusal before editing.** Run the smallest approved prepare-only trial with egress denied and a fresh single-use generation. Capture traceback file/function/line fields without exception messages, locals or authentication material. Instrument native command execution only to collect bounded metadata; return its bytes unchanged and retain the real clock, subprocess, kernel and proof readers. Label diagnostic instrumentation separately from the final qualification run. After refusal, read back cleanup and safe mode before another trial.
2. **Capture the representation at that boundary.** Use `docker inspect --format '{{json .}}' <owned-container-id>`, `iptables-save -t filter` and `docker top <owned-container-id> -eo pid,uid,args` as appropriate. Restrict collection to the pinned owned instance. Record selected security fields, flags and hashes; collect relevant `/proc/<host-pid>/status` fields while Chromium remains alive. Record exactly which fields were observed: a filter/namespace snapshot leaves capability facts unobserved when CapEff was omitted. Avoid copying full environment values, process arguments, page data or profile bodies into reports.
3. **Verify seccomp content against an independent authority.** Docker CLI can resolve a profile filename into inline JSON stored in `HostConfig.SecurityOpt`. Read the approved root-protected profile through the production bounded/no-follow file reader and verify its raw content hash before comparing the inline readback. Require strict JSON with unique keys at every depth, finite values, a dictionary root and a byte bound; compare structures with scalar types preserved so `1`, `true` and `1.0` remain distinct. Preserve exact option cardinality, NoNewPrivs and AppArmor checks. Exercise missing profiles, read failures, wrong hashes, changed values, duplicate options and malformed JSON at each caller of a shared validator.
4. **Normalize only demonstrated firewall representation differences.** Continue selector normalization with each negation attached to its selector. For an exact ESTABLISHED/RELATED conntrack set, accept the two observed orderings while preserving every other token and rule position. Test rejection of NEW, missing states, duplicate states, negation, changed interfaces and altered jump targets; generic token sorting can erase enforcement semantics. Execute the native snapshot parser in the regression, since a fixture containing already-normalized rules can miss the real refusal.
5. **Derive Chromium roles from combined facts.** Capture actual main and renderer rows before treating a launch flag as a role discriminator. A renderer can inherit `--remote-debugging-pipe`; record its explicit type, binary, UID and kernel status alongside the main process. Turn the observed shape into a regression while retaining negative controls for ambiguous types, foreign binaries, wrong UIDs, bad proxy flags and disabled sandboxing. Keep namespace depth, additional seccomp filters and capabilities as independent checks. An observed inheritance pattern identifies a classification defect; qualify the resulting implementation on the host before reporting that defect resolved.
6. **Replay the real boundary after local GREEN.** Upload the shared validator with every importing caller, then read the installed file bytes back and compare their hashes with the exact source manifest; checking the incoming upload text alone leaves the installed revision unverified. Check the required owner, single-link and permission bounds on those files. Run the genuine qualification entry point with instrumentation removed. A later refusal proves progress only through the preceding checks; record its new boundary and retain the wider acceptance gate. Keep raw kernel snapshots, a passed runtime predicate, authenticated observation and the saved-answer flow as separate evidence levels.
7. **Prove result correctness with bounded owned canaries.** Run fresh single-use instances for two allowed condition sets that produce different results and one legitimate empty result. Verify requested/applied condition equality through the real observer. When the public fixture and observation schema are deterministic, independently construct the expected canonical UTF-8 body and compare its exact byte count and SHA-256 with the authenticated result; compare the final-URL hash as well. A signed `found` category alone leaves contents unverified. Retain hashes and public fixture expectations rather than source bodies or tokens. Require final safe mode, container absence and residual-socket absence after every case. Label the elapsed interval by its actual start/end stages and retain small-sample scope; these canaries establish the owned recipe and runtime path, while real model, storage and saved-original qualification remain separate.
8. **Advance to the product wiring boundary.** Read the running application's service construction and durable worker admission paths after the runtime canaries pass. Locate the actual injected transport, contract, evidence writer/reader and provider client; distinguish an optional service returning `None` from an operating dispatcher. Select the smallest authorized live slice that reuses those components and preserves the original deadline, lease and attempt limits. Keep a single-shot operator harness scoped to qualification until the deployed transport, authorization and supervisor ownership are exercised.

### Cloud-worker delivery qualification

Use when moving an operator-run collector into an existing cloud worker.

1. Read the deployed startup command and resolve its application object. Register start/stop ownership on that object's lifecycle and test shutdown as well as startup; imports or hooks on a separate API application can leave the real worker idle. Confirm that the deployed package contains the collector and its dependency closure before enabling settings.
2. Probe from the actual worker container: executable availability, managed-identity access to the exact VM resource, secret retrieval, TCP delivery and verified TLS readiness. Report each boundary separately. For a worker without private routing, test the existing public endpoint before adding networking resources. On Azure, verify NSG enforcement from that worker: public inbound can be translated to the VM's private destination before NSG evaluation.
3. Generate OpenSSH known_hosts entries as `host key-type key-data` for port 22 and `[host]:port key-type key-data` for nonstandard ports. Use a trusted pinned host key and prove both successful delivery and wrong-key rejection with the real SSH client; a mocked argv assertion can preserve an unusable standard-port entry.
4. Restrict the deployment key to a forced command with forwarding, PTY and user-rc disabled. Preserve existing authorized keys. Send malformed input through that key and require a bounded rejection without shell output, then send one valid envelope and read back the receiver's receipt.
5. Trace the envelope through generation minting, bootstrap identity validation and actual slot preparation. Keep CLI and REST provenance truthful and validate the producer's exact shape at every reader. Record repeated preparation failures as a failed qualification and keep automatic collection disabled until the complete path passes; delivery receipts alone establish transport acceptance.
6. Apply settings with collector and browser admission disabled while preparing the deployment. Read back secret-reference resolution and readiness without printing secret values. Enable collection only after the deployed code and host validators are qualified, then observe automatically refreshed generations and two consecutive jobs with the operator collector stopped. Exercise stale-proof refusal separately.

### Control-plane mutation readback

Use explicit output handling for each Azure CLI operation. Read commands that require JSON should request an object projection and validate its shape. A successful mutation can return an empty body: use `--output none` when its response body is unnecessary, then perform a fresh read of the exact resource. For example, remove the approved pull identity with `az vm identity remove --ids <vm-resource-id> --identities <identity-resource-id> --output none`, then read `az vm show --ids <vm-resource-id> --query '{identity:identity}' --output json` and require the expected detached state before workload admission.

For an approved trusted repull that temporarily needs metadata access, first verify workload absence and save the exact runtime NSG rule. The AzurePlatformIMDS destination tag supports the Deny control; a bounded Allow trial can use the literal metadata address `/32`. Restore both the destination tag and Deny in finally, detach the exact pull identity and read back both resources before executing the browser. Record restoration independently from the pull result.

For controller-only iterations, reuse an already pulled immutable image only after checking its actual local digest, retained genuine pull binding and credential-cache absence. Keep fresh control-plane identity proof and source-hash verification for each new admission. This avoids unnecessary identity reattachment and image pulls while preserving the trust gate.

### Bounded CONNECT-proxy qualification

1. **Freeze the policy and enforcement owners.** Record code hashes and explicit hostname/IP, admitted peer, connection/header/byte/time budgets, UID and service limits. Identify which controls belong to deployed code and which the operator adds for the trial; a bootstrap presence check cannot attest independently injected OUTPUT rules. Keep browser forwarding default-deny and add only an interface/source-IP/gateway/port-qualified INPUT exception. Place its deny fallback before shared ESTABLISHED accepts so disabling the exception blocks old client packets.
2. **Prepare the trusted process without weakening privileged directories.** Run proxy code from a root-owned path traversable by its dedicated unprivileged UID. Preserve root-only bootstrap and credential-directory permissions; a readable script under a root-only parent still cannot execute as that UID. Restrict proxy-UID OUTPUT to the pinned site, trusted resolver and exact gateway proxy-port replies to the admitted client; missing reverse traffic prevents TCP admission. Bind a protected per-service resolver file when the system resolver stub introduces another trusted forwarding path.
3. **Establish usable DNS controls before launching the proxy.** Resolve the same owned hostname successfully from the trusted host, then attempt it from the browser container with a non-resolving bridge DNS target. Record Docker version and `ss -lunp`/`ss -lntp` listener state, including wildcard and gateway port 53. Pair failure with INPUT DROP deltas and uplink packet metadata; an NXDOMAIN-shaped name can fail even when DNS is permitted. Scope the result to the observed resolver/network-namespace configuration and require a fresh check after resolver or Docker changes.
4. **Make captures and service readiness observable.** Read the capture stderr descriptor until the listening marker; buffered readline plus select can hide an already buffered second line. Verify listener/service readiness from live state rather than historical journal matches, and scope journals to the current invocation or time window. Capture only packet headers, fixed categories and bounded counters.
5. **Exercise both INPUT branches before rebuilding.** Pair an approved CONNECT/TLS exchange with an application response from the owned fixture and capture `iptables-save -c` immediately afterward. Probe the live proxy from a second non-root, capability-free container with a different source IP, then capture the terminal DROP delta. Keep both snapshots before the next restore, because chain replacement resets counters. If platform ingress blocks the owned fixture, temporarily allow only the qualification VM source when authorized, then remove the exact rule and retain sanitized access-rule readback.
6. **Normalize malformed resolver output at the rejection boundary.** Require every address parser failure to raise the proxy's fixed rejection type and follow the normal denial response/counter path. Test malformed non-IP answers with that exact exception type; accepting either a domain rejection or bare ValueError in a test can conceal inconsistent connected error handling even when both paths close the socket.
7. **Observe replacement and natural expiry.** Run finite forbidden-connection probes during repeated firewall replacement, then observe proxy and workload deadlines without substituting manual stop. Record listener, child and container absence and distinguish an identity-admission refusal from proxy-policy verification. Retain shared-IP TLS, allowed-host exfiltration, conditional-site/redirect/CDN and per-job authentication gaps explicitly.
8. **Verify cleanup after its last mutation.** Stop the proxy cgroup before removing its UID enforcement, restore the deny-only INPUT policy, and remove every matching owned IPv4/IPv6 OUTPUT hook with a bounded loop while preserving unrelated rules. Read `iptables -S OUTPUT`, `ip6tables -S OUTPUT` and the table inventory after deletion, then verify the owned chain, listener and UID processes are absent. On nft-backed hosts, use `iptables-save -t filter` or `nft -j list table ip filter` to confirm chain inventory when a missing-chain query yields an ambiguous compatibility diagnostic. Record retained service accounts separately from running processes. Parent-finally cleanup proves that trial's cleanup; supervised recovery after caller loss or SIGKILL needs its own test.

### Supervised-controller qualification

Use after the CONNECT proxy and host enforcement are frozen. Keep the controls below in the deployed controller rather than depending on a parent trial's finally block.

1. **Pin immutable instance ownership.** Install one systemd template whose ExecStart and ExecStopPost both use `%i` as the generation. Keep the active job's protected policy unchanged and serialize jobs. While generation A runs, issue daemon-reload, try generation B, and request stale cleanup; require A's state, PID and cleanup generation to remain bound. A state fence cannot repair a fixed unit whose future ExecStopPost command was re-rendered for B.
2. **Admit against trusted host configuration.** Under the bootstrap mutation lock, require the submitted own-public-IP policy to equal the existing protected binding. Preserve the original configuration line, including quoting/export form. Reject missing, duplicate or shell-expression values; replacing the host binding can remove the intended own-host egress restriction.
3. **Check restart eligibility before consuming proof.** Run `ss -H -tan "sport = :${PROXY_PORT}"` with a finite command timeout before state/config writes or one-use identity-proof consumption. Reject query failure or any residual socket state. Keep cleanup's process/listener absence check separate, because TIME-WAIT can survive successful cleanup. Reproduce server-side TIME-WAIT and immediate rebind errno on the actual host with the frozen proxy and a loopback-only forbidden request; retain that mechanism evidence separately from an earlier invocation whose errno was never recorded. In the rejection test, compare proof, state and config hashes before/after. Observe port clearance with a bounded state check for a later operator trial; keep production scheduling policy explicit rather than adding blind sleep, retry or socket-reuse changes.
4. **Verify exact live firewall readback.** Normalize independent source/destination/interface selectors from actual `iptables-save` fixtures, moving any `!` together with its selector and value while preserving module order and full equality. Require valid filter-table framing and COMMIT; empty output must fail verification. Exercise negative-rule deletion as well as comparison, since a separated negation can make cleanup delete the wrong rule or fail.
5. **Close each lifecycle combination.** Run an owned external request with application HTTP success, TLS and live renderer sandbox facts, then let that same instance expire naturally. Separately test SSH loss with the same MainPID still active, another generation's refusal, stale cleanup and MainPID SIGKILL. Use `systemctl show "$UNIT" -p ActiveState -p Result -p ExecMainCode -p ExecMainStatus -p MainPID -p ExecStopPost` and `systemctl kill --kill-who=main --signal=SIGKILL "$UNIT"`. Read back safe mode, deny-only INPUT, all owned IPv4/IPv6/nft OUTPUT absence, UID processes, listener and container absence. An intentional SIGKILL can leave Result=signal while cleanup succeeds; check cleanup status/errors separately. Browser success followed by parent manual stop and a separate browser-free expiry test leave the combined lifecycle unproved.
6. **Bound recovery claims.** Calculate the supervisor budget from admission, readiness, useful work, every bounded cleanup command and retries; a finite watchdog can still interrupt the slowest cleanup path. Keep ownership fences on corrupt state and document the deny-first privileged recovery path. Treat worst-case timeout completion, corrupt-state recovery, VM reboot and crash as separate acceptance gates until exercised. Preserve the interrupted result when cleanup succeeds instead of rewriting it as a normally completed job.

## 7. Diagnose the constrained resource

| Evidence | First response | Expansion decision |
|---|---|---|
| Backlog grows, local slots occupied, quotas healthy | Check fairness, duplication and occupancy | Add slots only if throughput/tail wait improves |
| CPU/thread/event-loop wait grows | Find blocking or local compute hotspots | Expand remaining demonstrated local pressure |
| RSS/OOM/restarts track sessions | Check leaks, tab lifetime and concurrency | Size from stable per-session requirements |
| Provider admission/429 grows with idle local CPU | Reduce/pacing calls and inspect quota | Change provider capacity, not unrelated replicas |
| One site dominates delay or blocks | Apply site-specific limits or authorized alternatives | Do not grow globally to evade restrictions |
| DB calls/locks/RU/throttling grow | Inspect queries, hot partitions and claim contention | Change storage capacity/structure only for remaining limits |
| Connection/bytes dominate | Reuse connections, reduce payload, inspect placement | Change the demonstrated path constraint |
| Conditions/evidence wrong with spare resources | Fix execution/validation | Scaling cannot establish correctness |
| Collection or attribution missing | Repair measurement/completeness | Defer automatic capacity decisions |

Record the evidence window, coverage, hypothesis/alternatives, old/new settings, incremental total cost, observed effect and rollback. Distinguish visible messages, leased work, delayed retries, cancellations and durable unfinished jobs; queue length alone is insufficient.
