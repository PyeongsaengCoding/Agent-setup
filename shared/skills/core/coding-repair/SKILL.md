# 수정·재개

남은 목표, 실패한 검사, 현재 변경 상태부터 확인한다. 이미 생성한 코드와 커밋을 보존하고 실패 근거에 맞춰 수정한다.
같은 실패가 반복되면 새 근거 없이 동일한 시도를 반복하지 말고 가설·접근을 재평가한다. 네트워크의 일시 실패와 테스트의 동작 실패를 구분한다. 외부 부작용이 있었는지 알 수 없으면 같은 작업을 무작정 재실행하지 않는다.
해결되면 같은 시나리오를 확인한다. 해결 불가이면 실패 근거·남은 상태·필요한 입력을 남긴다. 무한 재시도나 자동 모델 승격을 지침만으로 구현됐다고 주장하지 않는다.

## 반복 수정 주기

여러 번 고치고 확인하는 주기를 시작하기 전에 다음을 기록한다.

- 끝을 판정할 명령과 기대 결과. "깔끔해진다" 같은 형용사는 명령과 결과로 바꾼다.
- 수정하면 안 되는 범위와 시작 커밋 SHA. 기존 테스트·픽스처, 검사 명령이 실행하는 파일, 린트·CI 설정, 사람이 정한 한도를 넣는다.
- 수정 담당과 다른 판정자, 같은 항목의 재시도 상한.

판정자는 검사를 직접 다시 실행하고 시작 커밋 대비 diff를 읽는다. 테스트 삭제·건너뛰기, 느슨해진 단언, 실패를 가리는 mock, 삼킨 오류, 늘린 한도로 얻은 통과는 실패로 판정한다. 재시도 상한에 닿으면 그 접근을 멈추고 다른 접근을 찾고, 남은 접근이 없으면 이유와 함께 막힘으로 기록한다.
판정을 통과하면 이번 주기에서 바뀐 파일로 범위를 한정해 정리하고 같은 검증을 다시 실행한다. 검증이 회귀하면 정리를 되돌린다.
