# 제품 문구

문구의 생성 위치와 표시 조건, 사용자 행동에 필요한 정보를 추적한다. 중복, 행동 없는 안내, 내부 구현 노출, 의미 없는 확인을 후보로 정리한다.
오류 설명·법적 고지·되돌릴 수 없는 행동 확인은 목적과 제품 계약을 확인한 후 판단한다. 말투 취향만으로 삭제하지 않는다. 화면 점검 항목은 검토 질문으로 쓰고, 목적이 확인된 항목은 유지한다. 조사 요청은 파일·조건·이유·제안으로 끝내고, 수정 요청은 실제 표시와 흐름까지 확인한다.
정리를 수정한 담당은 그 정리를 승인하지 않는다. 검토는 파일을 고치지 않고 수정 계획·diff·전후 확인 결과를 읽어 coding-code-review 형식(심각도, 반영 가능 여부)으로 보고한다. 검토에서 나온 수정은 다시 수정 담당에게 돌린다.
