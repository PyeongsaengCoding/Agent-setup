# 완료 검증

현재 변경과 요구사항에 맞는 최소 충분 검사를 고른다. 각 검사에 대상 revision, 시나리오, 기대 결과, 실행 명령 또는 도구, 관찰 결과를 연결한다.
계획한 검사와 실제 통과한 검사를 분리한다. 실패는 수정 후 관련 검사를 재실행한다. 코드가 바뀌면 영향받는 증거를 갱신한다. 개별 담당 테스트 통과를 합쳐진 코드의 통합 통과로 확대하지 않는다.
코드, 로컬 테스트, 실제 화면, 외부 계정, 배포를 구분해 보고한다. 미실행·오래된 증거로 완료나 배포 성공을 주장하지 않는다.

## 실패한 검사의 원인

실패한 검사마다 원인을 `변경으로 생김`, `기존 실패`, `미확인` 중 하나로 적고 근거를 붙인다.

- `변경으로 생김`: 같은 명령이 merge-base에서 통과하거나, 실패 위치가 이번 diff가 추가·수정한 줄이다.
- `기존 실패`: merge-base를 깨끗한 분리 worktree(`git worktree add --detach <dir> <merge-base>`, 확인 후 제거)에서 같은 명령으로 실행해 같은 방식으로 실패했다. 사용자의 작업 트리는 stash·checkout하지 않는다.
- `미확인`: 위 두 근거가 모두 없다.

merge-base 실행 결과는 관찰이고 diff 줄 판단은 추론이다. 둘이 다르면 merge-base 실행 결과를 따른다.
필수 검사가 하나라도 실패하면 원인과 관계없이 완료로 판정하지 않는다. `기존 실패`는 그 merge-base 실행을 근거로 변경 책임이 없는 보류로 보고하되, 실패한 실행이 변경된 코드까지 실행했을 때만 그렇게 한다. 수집·import 오류처럼 변경을 실행하기 전에 멈춘 검사는 증거 없음으로 둔다. `미확인`은 merge-base 실행을 빠진 증거로 적은 보류로 보고한다.
