# 제품 화면 제작과 검수

새 시각 방향을 정하는 화면 작업은 실제 제품 레퍼런스 최소 5개를 추천하고, 사용자가 고른 주 레퍼런스와 채택할 요소를 확인한 뒤 구현한다. 이미 선택한 디자인 방향의 화면 확장·수정은 그 기준으로 구현·검증한다. 프로젝트의 디자인 기준(DESIGN.md, 프로젝트 지침)이 있으면 함께 따른다.

## 제품 레퍼런스를 화면으로 옮기기

새 화면을 만들거나 색·글꼴·배치를 의미 있게 바꿀 때 적용한다. 작은 문구·간격 수정은 기존 방향을 재사용한다.

1. 현재 제품의 실제 화면·디자인 기준과 사용자가 제공한 레퍼런스를 확인한다. 새로운 시각 방향이면 제품에 맞는 실제 사이트·화면 사례 최소 5개를 원본 링크·추천 이유·채택할 요소와 함께 제시하고, 사용자가 주 레퍼런스와 요소를 선택할 때까지 그 방향의 구현을 기다린다. 이미 선택한 방향을 이어가는 작업은 현재 기준을 사용한다.
2. 사용자 목적과 선택한 레퍼런스에서 가져올 요소를 연결한다. 색의 역할, 글꼴·제목/본문 위계, 여백·정보 밀도, 배치·작은 화면 동작을 구현에 필요한 만큼 구체화한다. 해당 제품의 기존 디자인 토큰·컴포넌트를 우선 사용한다.
3. 선택한 기준으로 요청 범위를 구현한다. 레퍼런스의 인상을 제품의 실제 정보·행동에 맞게 옮기고 기존 브랜드·사용 흐름·접근성을 보존한다.
4. 실제 화면에서 레퍼런스의 선택한 요소가 반영됐는지와 가독성·정보 우선순위·작은 화면·핵심 조작을 변경 범위에 맞게 확인한다. 참고한 요소와 제품에 맞춰 달리한 부분을 짧게 설명한다. 지침 적용과 실제 화면 검증을 구분한다.

## 구현과 검증 경계

- 기존 제품 결정과 디자인 기록은 설계 근거로 참고한다. 배포·게시·유료 호출·계정·데이터 변경은 해당 작업의 권한 경계를 따른다.
- 변경 대상의 코드와 실제 화면을 좁게 확인하고, 구현 후 변경을 증명하는 가장 작은 충분한 화면·동작 검증을 수행한다.
- 비교가 필요하면 실제 제품 캡처나 검증된 렌더로 같은 화면·viewport·데이터·상태를 비교한다. 레퍼런스 추천과 선택은 새 시각 방향에 적용하고, 채택된 방향의 작은 수정은 기존 기준으로 진행한다.
- frontend와 backend가 별도 Git이면 각 Git 루트와 연결된 제품 계약을 확인하고 필요한 범위만 구현·검증한다.
