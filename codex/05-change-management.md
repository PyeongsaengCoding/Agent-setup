# 구성 변경·업데이트·복구

Codex 전용 원본은 현재 Agent-setup 체크아웃의 codex/다. 전역 지침은 shared/rules/, 공통 스킬은 shared/skills/에서 관리한다. 공용 지침·스킬 변경은 원본→검사→적용→발견→실제 과제 검증→결과 기록 순서로 수행한다. 제품별 지식은 해당 repo가 소유한다.

- GAM 프로그램은 공식 `uv tool install`의 기본 경로를 사용하고, 기존 codex-setup 상태 경로에 별도 Python 환경을 만들지 않는다. 버전을 바꿀 때는 `uv` 관리 도구와 macOS 서비스·Codex MCP 연결, 별도 Ollama 서비스·설정된 임베딩 모델의 실제 응답을 함께 확인한다. GAM 업데이트가 Ollama 자체를 설치·업데이트한다고 가정하지 않는다.
- 설치 도구와 스킬의 버전·출처를 기록한다. 설정을 맡은 AI는 각 도구의 공식 최신 안정판과 스킬의 최신 안정 릴리스 또는 최신 검토된 upstream 커밋, 대상 계정·macOS 호환성을 확인한다. 원본 차이·라이선스·설치 방식 변경을 검토하고 관련 회귀·행동 과제를 통과시킨 뒤 사용자 홈에 적용한다. 기본 갱신은 전체 폴더가 설치 당시 원본과 일치할 때만 수행한다. 사용자가 기존 스킬의 최신화를 요청하면 대상 전체를 확인하고 각 폴더를 비공개 상태 경로에 백업한 뒤 교체·검증한다. 실패하면 백업으로 복구하고 이유를 남긴다.
- 사용자 config 전체를 교체하지 않는다. 관리 MCP 블록만 병합하고 충돌한 비관리 항목은 그대로 보존해 보고한다.
- 변경 전 Git 저장소 밖의 비공개 백업 경로에 내용과 적용 후 해시를 기록한다. 설치 상태 백업은 사용자 홈의 `Library/Application Support/codex-setup/`에 둔다. `setup_runtime.py restore --backup <폴더>`는 적용 이후 사용자가 수정한 파일을 자동 덮어쓰지 않는다.
- 핵심 스킬은 사용자 홈에 복사하고 검증된 복사본만 백업 후 갱신한다. 사용자가 수정한 복사본은 보존해 차이를 보고한다. Setup 체크아웃은 재설치·업데이트의 원본이며 평소 스킬 실행 경로는 아니다.
- 외부 설치물이 새로 보인다는 이유만으로 원본에 수집하지 않는다. 인증·세션·기억·DB·로그·계정 이메일·프로젝트 식별자·포트 배정·개인 설정 원문은 Git에 넣지 않는다. 프로젝트별 파일은 설치 대상으로 삼지 않는다.
- 설치 결과와 실제 동작은 12의 기준에 따라 구분해 보고한다. 실행 기록은 Git 밖 상태 경로에 두고, 원격 게시는 현재 사용자의 요청 범위에서 수행한다.

정기 기록 정리의 정책은 config/retention.json이다. 스케줄 등록과 실행 결과를 따로 확인한다. 같은 요청의 승인 범위를 반복 질문하지 않으며 배포·게시·별도 계정 계약을 확대하지 않는다.

## 기존 Codex-Setup 설치 이관

1. Agent-setup 전체 체크아웃과 그 안의 codex/를 확인한다. 공통 스킬은 형제 폴더 shared/skills/에서 읽는다.
2. 비공개 상태 경로의 installation.json과 기존 전역 AGENTS.md를 읽어 이전 원본 경로와 사용자 수정 여부를 확인한다. 기존 상태·백업·서비스 이름 codex-setup은 유지한다.
3. 새 codex/에서 설치 계획을 확인하고 적용한다. 사용자 수정으로 보존된 지침은 차이를 검토해 현재 승인 범위만 병합한다. 적용 뒤 installation.json의 setup_root가 새 codex/ 절대 경로인지 확인한다.
4. 새 Codex 작업에서 스킬·도구 발견과 실제 응답을 확인하고, 원본 전환·홈 적용·실행 검증 결과를 구분해 보고한다.
