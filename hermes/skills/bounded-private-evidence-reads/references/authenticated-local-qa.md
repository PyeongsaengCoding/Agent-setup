# Authenticated local QA with real private sources

## 1. Freeze the smallest complete acceptance path

List the expected account/Workspace, exact private source scope, production GETs, local writes, provider call budget, actual components, worker execution, reload and cleanup. Keep already approved setup within that boundary. Ask when an account, resource, source corpus, persistent change or spending scope expands.

Prepare the final UI and auth origin before generation. Reuse an available origin's normal SDK restoration when supported and owned. When using a genuine bearer admitted through a production identity GET, label the local mechanism proxy admission and retain the product-signature/login coverage as a separate check.

## 2. Prove isolated plumbing before reading private originals

1. Scrub inherited service configuration before importing application modules with cached settings.
2. Bind stores and writers to RAM or approved private local storage; disable automatic production workers, scheduled title/model work and unrelated retrieval.
3. Restrict network hosts and methods to the selected identity/data GETs and explicitly allowed provider transport.
4. Run synthetic route/store/worker checks with real HTTP handlers. Keep this result labeled synthetic.
5. Independently test that each concrete provider opener reaches the call counter and rejects over-budget dispatch before network access. Use a controlled opener response; a fake model callback can bypass the transport entirely.

## 3. Admit the exact actor and source

Read current login identity and the full selected Workspace id through the genuine SDK context. Verify server identity, role, active membership, provider account identity, consent and serving status before content reads. Obtain the tenant and document keys from authenticated identity and current mapping code; avoid deriving tenant ids from Workspace naming patterns.

Read only the approved bounded source. Preserve source timestamps and source identity while inserting it through the application record writer. Assert the consumer can find that source before spending a model call. Keep originals and credentials in memory when retention is restricted.

## 4. Run one connected question

Use a generic natural question whose answer depends on the authorized source. For semantic source-discovery coverage, omit literal source-type keywords. For a required fresh-data branch, express latestness naturally and observe the model's choice; retain the actual successful-sync timestamp.

Submit through the application route and retain the conversation, turn and instruction revision. Observe consent, execute the actual stored-data choice, and run the supported worker tick. Bound model calls across proposal, tool-result synthesis and permitted correction steps.

Verify:

- Original user text, turn and instruction revision remain identical.
- Exactly the expected user and assistant messages are saved.
- Current citations refer to the admitted source; excerpt, original-body hash and state token still validate.
- Citation markers occur in the answer and only authorized references reach the model.
- Real progress, elapsed time and completion state are saved.

## 5. Reopen while the private state remains available

First compare the saved raw answer and API answer hashes. Reload the actual product component/page, wait for settled restoration and compare its DOM with the stored answer using presentation-only normalization. Exercise completed-history keyboard toggles and the requested viewport widths.

Run terminal worker replay and assert identical authorized output with zero additional model dispatches. Check unauthenticated and wrong-Workspace refusal separately. Keep the RAM process alive through these checks; a hash receipt cannot recreate a discarded private answer.

## 6. Preserve evidence and close owned resources

Save exact commands, exits, source/code fingerprints, safe authority flags, source-validation booleans, raw-answer and history hashes, dispatch measurements and remaining stage gaps. Preserve each attempt's receipt before rerunning.

For private screenshots, measure the unmodified DOM first, then cover confidential regions with opaque overlays that preserve layout; verify the saved image contains no private source or answer text. Keep general progress controls visible for visual QA.

When a transport ledger was not attached, record measurement uncertainty and the independent connection/model-step observations. Repair and test the counter before the next live run; an empty ledger establishes no call total.

Close only owned tabs and processes, clear retained credential variables and verify the owned ports after shutdown. Keep API, actual component UI, complete authentication, provider acquisition, search readiness and deployment as distinct verdicts.
