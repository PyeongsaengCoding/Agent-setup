# 코드 구조

## 적용 범위와 완료 기준

- 코드 프로젝트에서는 CodeGraph를 기본 탐색 수단으로 쓴다. 실제 코드가 있는 Git 루트마다 상태를 확인하고, 별도 frontend/backend 저장소는 각각 관리한다. 문서·미디어 전용 폴더는 코드 색인 범위에서 뺀다.
- 스킬은 작업 절차, MCP는 실행 도구, 프로젝트 색인은 조회 데이터로 설명한다. 설치·연결·색인 존재·실제 조회 성공을 각각 확인하고 보고한다. 이미 설치된 도구에는 필요한 초기 적용·갱신 단계를 제시한다.
- MCP가 색인 부재를 반환하면 그 응답과 현재 권한·도구의 초기화 지원을 확인한다. 승인된 대상에서만 색인을 만들고 다시 조회한다. 초기화 권한이 부족하면 그 단계를 승인 대기로 남기고 소스 직접 탐색으로 요청 작업을 이어간다. 색인 없는 같은 조회를 반복하면 실패만 쌓인다.
- 최초 적용의 완료 기준은 저장소에 실제로 있는 심볼의 조회 성공이다. 코드 변경 후에는 갱신 필요성을 확인하고, 질문마다 전체 색인을 다시 만들지 않는다.
- 전역 적용은 규칙 작성·실행기별 설치·프로젝트 초기 색인·실제 조회를 별도 단계로 잡는다. 설정 문서만으로 전 프로젝트 적용 완료를 보고하지 않는다.

## 사용

실제 Git 루트를 확인한다. 연결된 CodeGraph MCP 도구가 있으면 그 도구를 먼저 사용한다. MCP 도구가 없으면 설치 기록(Codex: `~/Library/Application Support/codex-setup/tools.json`)의 codegraph 경로나 PATH의 codegraph CLI를 사용한다.
CLI는 codegraph status로 상태를 확인한다. 최초 작업에서는 대상 Git 루트에서 codegraph init --yes, 변경분이 남았으면 codegraph sync를 실행한다. codegraph query 또는 explore로 심볼·호출자·영향을 좁히고 해당 원본 파일을 읽는다. CLI 구문은 설치 버전 --help로 확인한다.
그래프 결과가 없거나 동적 호출을 다루면 rg와 원본 추적을 함께 사용한다. 인덱스 검색 결과를 정확성이나 테스트 통과 증거로 취급하지 않는다. 무관한 저장소나 홈 전체를 색인하지 않는다.
