# Saved-source contention retry

## When to Use

Use for a narrowly authorized bookkeeping transition during saved-source reads.

## Guard and verification discipline

- Write an end-to-end failing first-open test before changing production guards; exercise the service and HTTP surface with a CAS metadata fixture and a bounded external-bytes callback.
- Inject the actual title writer between the outer conversation read and the outer turn read, as well as during body I/O. A stale pending/attempted parent can pair with a completed turn whose title_pending is already False; body-only races miss this causal snapshot boundary. Preserve the resulting RED and real first-open failure separately from restarted-source recovery.
- Keep direct readers fail-closed. Signal narrowly classified contention through a private typed denial subclass; consume it only after every outer protected-row and baseline authority fence passes.
- Compare full type-sensitive canonical JSON, removing only the specifically authorized bookkeeping keys. Preserve bool/number and missing/null distinctions, unknown fields, and revision checks.
- Capture the full parent and turn from the same reads that produce each authority ETag snapshot; validate every observed intermediate state and the aggregate transition. For generated titles, enforce the actual pending→attempted (+1), attempted→generated/unavailable (+1), pending→generated (+2), and pending→unavailable (+1 skipped or +2 attempted) writer paths. Preserve updated_at and all other parent fields.
- Bind parent title contention to the exact retained first user message and completed turn, capture that message before body I/O, and recheck its full body/ETag alongside the answer and frozen input. Anchor both the proven after-parent and after-turn on the single fresh attempt; a second title write during that attempt stays denied.
- Admit a stale pending/attempted parent with title_pending=False only when a later exact terminal parent CAS and an identical full completed turn prove the writer-order split. Close a split at the final authority boundary with the existing proof read, checking both the adjacent and aggregate transition before anchoring its parent/turn.
- Preserve full answer/frozen/question bodies in the retry anchor, and recheck protected rows after the fresh attempt's final authority observation. Reuse the already validated frozen point reads to fund those fences within existing metadata ceilings; retain the earlier post-body row checks so a second parent change at a protected read remains observable.
- Recheck all non-transition authority rows and protected answer/frozen rows after observing the changed turn; a turn-first early raise can hide simultaneous mutations.
- Anchor the full fresh attempt to the original actor/context, citation/reference, protected id/ETags, non-transition authority snapshot, and proven after-turn. Reject branch switches and ordinary error-code retries.
- Share one request-local monotonic admission/result deadline across both attempts; guard point reads and body callbacks before/after I/O, retain interruption, and admit at most two body reads. Document uncancellable callback limits instead of claiming hard termination.
- Pin metadata/body operation ceilings and adjacent non-browser source behavior. Avoid widening architecture budgets when shared files already carry unrelated dirty work.

## Real authenticated application checks

- Read actual runtime entry-point names before injecting a transport. Bind the application request state, application-global consumer, and module-global service to one checked QA runtime; tests should detect stale entry points and refuse foreign settings before mutation.
- Use execution-pool values accepted by the product. Isolate QA storage and preflight existing eligible work before running a standard batch; arbitrary QA labels can normalize to another pool or be refused.
- Project browser applied conditions and retained URL only from evidence already verified against the whole body hash, committed result, frozen reference and final authority fences. Preserve operation ceilings and private identifiers; distinguish requested parameters from actual post-submit readback, and backend staging timestamps from browser capture time. Confirm actual saved-instance values through genuine API and UI reads rather than source inspection alone.
- When a source-panel region locator times out, preserve the failure and inspect its live labelled DOM, visibility and snapshot before classifying it as a product failure. Verify the same panel through an exact supported selector; keep source deadlines and retry policy unchanged.
- Read router declarations and response schemas before constructing the HTTP capture. Verify the real citation-source route and nested message text with a bounded external ASGI fixture, then exercise genuine bearer verification and source reads without dependency overrides. Saved browser source text is in source.messages[].text; a top-level text/content fallback can hash an empty string even when HTTP200 carries the correct source. Reject a missing schema field and preserve the failed harness extraction separately from corrected product evidence.
- Trigger the source request immediately after the client's final or persisted-completion event in a single-lifetime smoke. Preserve a timeout as a failed acceptance result; record later restarted-API recovery separately and link its exact saved conversation, turn, and source instead of rewriting the original failure as a pass.
- Test actual loopback TCP disconnect separately from synthetic ASGI task cancellation. Synchronize the callback entry and protocol connection_lost, measure borrowed worker tokens until the callback really finishes, and distinguish an app-generated response from client-received bytes. Passing reproduction assertions document existing gaps; they do not prove cancellation recovery.
- Trace interruption through the real storage adapter as well as an injected callback. An adapter's broad exception wrapping can turn InterruptedError into a different refusal; a callback-only HTTP500 proves that callback surface. Do not claim abandoned threads are terminated or server-side SDK timeout parameters bound client socket waits.
- Inspect the installed SDK's downloader and throttle retry loops as well as pipeline settings. Prove active request-scope transport guards against repeated I/O and inactive pass-through; retry_total=0 alone can leave internal Blob short-body and Cosmos throttle retries. Test slow trickle separately from a stalled socket because per-read timeouts can pass work beyond the overall budget.
- Keep worker ownership and its capacity permit until the synchronous callback actually returns, including raw task cancellation and TCP disconnect. Use a single ASGI receive owner, preserve middleware body semantics, and test saturation without starting another callback. Record overload and request-body policy scope before changing a shared citation endpoint.
- Test saturation through the actual authentication/workspace middleware. Membership and closed-beta reads can queue on the same limiter before route-level admission; a fixture identity or call_next-only wrapper misses that ordering. Cover disconnect while queued and confirm no later membership/body I/O.
- Advance the controlled deadline inside the awaited outer header send and after the first body chunk, then assert the next source bytes are refused. Checking before serialization or only before headers leaves post-await and subsequent-body gaps. Preserve already-committed HTTP status semantics when aborting expired content.
- Distinguish cancellation of the outer request from cancellation of the supervised worker task itself. Reproduce both before callback entry and during I/O, and verify reservations and actual worker reuse separately.
- Reserve authentication I/O only after verified bearer checks, reuse the existing limiter, and exercise request-body arrival while auth I/O is pending. Test ordinary queued authentication separately so a source-only overload policy stays scoped to citation-source requests.
- Exercise asyncio.Runner.close() against a running supervised worker and prove same-thread reuse after cancellation. Keep ownership through AnyIO idle publication, release reservations for never-started work, and report shutdown delays for uncooperative callbacks.
- Separate the time a successful ASGI send hands bytes to Uvicorn from the time a slow TCP client receives them. Fence each subsequent source-body send; preserve already-committed status and record any bytes authorized before expiry that finish afterward.
- Before live frontend QA, verify native identity-provider account lookup from the actual development origin in addition to backend bearer verification. A cached genuine JWT can pass the backend while frontend session restoration fails on API_KEY_HTTP_REFERRER_BLOCKED. Test an explicitly allowed origin and preserve failed-origin evidence; a wildcard in a settings list alone does not prove provider admission. Keep provider policy unchanged and never persist restored session tokens in QA files.
