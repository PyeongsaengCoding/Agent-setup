# Editing-Tool Adoption

Use this note when a user selects an agent-oriented video editor for a production project.

1. Separate editing from generation. Identify which exact source assets, approved audio, script, timing, and captions the current production workflow owns. Adopt the editor for timeline assembly and revisions without silently approving new generated assets or public publishing.
2. Record the selected editor as the preferred editing path when that is the user's decision. Keep untested installation, account access, agent compatibility, usage charges, and data transmission marked unverified; do not dilute the decision into permanent candidate status or inflate it into completed integration.
3. Prepare an editable project from source assets. Do not assume that importing a flattened MP4 reconstructs caption, image, audio, or timing layers; burned-in text is part of the picture, not recovered editable text.
4. Preserve production invariants across the editor change: exact product appearance, approved voice and dialogue, caption emphasis, safe areas, timing, rights, and completion/publishing gates. Express corrections by the relevant time, picture region, and intended outcome rather than rewriting the whole production plan.
5. Test an unpublished asset-copy project through a meaningful caption or cut revision, preview, final export, and reopen/re-edit. Inspect the full picture and sound plus actual resolution, aspect ratio, codecs, font rendering, synchronization, and safe areas. Treat saved project, playable export, and reviewed output as separate evidence.
6. Retain the established renderer for inspection, format conversion, or recovery until the new path is demonstrated. Report an actual fallback as a fallback; never label the old renderer's output proof that the selected editor worked.

Keep integration checks proportional to the first real production request. Do not create periodic rechecks, per-link obligations, new approval ceremonies, or manual editing work for the user.
