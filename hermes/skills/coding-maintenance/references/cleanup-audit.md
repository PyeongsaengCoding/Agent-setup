# 정리 조사와 승인 기준

## 1. 좁은 경로 발견과 메타데이터 조사

- 설치 기록과 작업 공간 지침에서 프로젝트 루트를 찾고, 직접 자식 디렉터리부터 조사 범위를 좁힌다. 광범위한 검색 결과가 제한되면 루트별로 나눠 재조회한다.
- `os.scandir()`로 이름·종류·심볼릭 링크 여부를 확인하고 `stat(follow_symlinks=False)`로 파일 수·논리 크기·수정 시각을 집계한다. 오류와 제외 경로를 함께 남긴다.
- 심볼릭 링크는 경계를 넘지 않도록 기본 제외한다. `.git`, 인증 폴더, 클라우드 보관 자료, 의존성 환경은 조사 목적에 따라 명시적으로 제외한다.
- 가상 환경 이름은 `.venv` 정확 일치와 `.venv-*` 같은 변형을 함께 처리한다. 버전별 환경을 놓치면 패키지 캐시를 제품 캐시로 분류하고 후보 수를 부풀릴 수 있다.
- 산출물 이름은 `outputs`와 함께 `build`, `dist`, `tmp`, `artifacts`, `exports`, `productions`, `deliverables`, 캡처·검증 폴더를 검토한다. 이름은 탐색 힌트로 사용하고 내용의 역할은 별도로 확인한다.
- 부모 후보를 한 묶음으로 집계하면 그 안의 자식 후보를 전체 합계에 다시 더하지 않는다. 하위 분해 표는 부모 용량의 설명으로 유지한다.

## 2. 후보마다 확인할 근거

| 대상 | 확인 | 보호·보류 조건 |
|---|---|---|
| Python bytecode | `.cpython-*`를 분리해 대응 `.py` 파일 존재 확인 | 소스가 현재 경로에 없으면 복구 가치와 Git 이력 확인까지 보존 |
| 모바일 빌드 결과 | 큰 중간 폴더별 크기·확장자·빌드 입력 확인 | APK/AAB/IPA, 키 저장소, 프로비저닝, dSYM, 심볼·소스맵은 별도 검토 |
| 제작·게시 자료 | 제작 상태·예약 등록·실제 게시·편집 원본 연결 | 진행 중 제작·게시, 재편집 원본, 게시 미확인은 보존 |
| scratch·임시 폴더 | 작업 복사본·원본 증거·활성 세션 연결 | 최근 배포 작업, 저장소·worktree, 미해결 증거는 보존 |
| 날짜별 납품 폴더 | 관련 프로젝트·최종본·작업 복사본 연결 | 날짜 이름과 별개로 역할별 분류 |
| 스킬 | 실행기별 SKILL.md 목록과 내용 해시 비교 | 다른 실행기의 동일 사본과 같은 실행기 내 중복을 나눠 판단 |
| 기억 | 서비스 상태·프로젝트 등록·색인과 원본의 범위 | 색인 0건 결과로 모든 기억 저장소가 비어 있다고 판단하지 않음 |

Git 추적 여부는 `git -C <repo> ls-files -z`를 읽어 후보 상대 경로의 접두사와 비교한다. 저장소·worktree·복사본 개수는 제품 수와 구분한다. 현재 인덱스 결과와 ignored 여부·코드 참조·실제 사용은 각각 확인한다.

프로세스 작업 경로는 `lsof -n -a -d cwd -F n` 같은 읽기 전용 관찰로 확인할 수 있다. 작업 경로에 나타나지 않은 대상도 열린 파일·서비스·예약 작업에서 사용할 수 있으므로 이동 직전에 해당 사용 상태를 확인한다. 프로세스 인자와 인증 환경값은 보고서에 복제하지 않는다.

빌드 입력과 wrapper가 존재하는 상태, 실제 재생성 성공, 앱 설치·실기기 동작을 각각 구분한다. 조사만 마친 상태에서는 재생성 검사를 완료했다고 보고하지 않는다.

## 3. 승인용 산출물

사람용 브리핑에는 다음을 포함한다.

1. 조사한 루트·제외 경로와 검토 규모.
2. 우선 후보의 ID·프로젝트·정확한 경로·논리 용량·수정 시각·선정 근거.
3. 보존 대상과 미확인 근거.
4. 승인할 행동, 격리 위치·보관 기간, 검증·복구·중단 조건.
5. 정리 실행과 정기 보고를 독립적으로 선택할 승인 문구.

상세 관찰 목록과 실행용 승인 목록은 따로 저장한다. 초기에 나이·Git 상태로 추린 후보가 이후 소스 검사에서 보류되면 최종 승인 목록에 그 판정을 반영한다. 원시 조사 라벨을 삭제 승인으로 사용하지 않는다.

승인 대상은 파일 상대 경로·크기·수정 시각과 필요시 inode/device 또는 내용 해시로 스냅샷을 만든다. 내용 해시는 필요한 범위에만 사용하고 인증 파일·고객 원문의 본문은 수집하지 않는다. 실행 시 스냅샷 이후 변경된 대상을 재평가한다.

전달 전 자동 검사로 다음을 확인한다.

- 목록 개수와 선언한 폴더·파일 수가 일치함.
- 파일 용량 합계가 승인 대상 용량과 일치함.
- 부모·자식 후보의 중복 집계가 없음.
- 현재 파일 메타데이터가 대상 스냅샷과 일치함.
- 조사 오류와 미확인 단계가 문서에 남아 있음.

## 4. 주기적 관리

주간 후보 보고, 월간 산출물·게시 상태 검토, 분기별 스킬·기억·색인 검토를 초기 제안으로 삼고 프로젝트별 보존 기간에 맞춘다. 기존 보존 설정, 예약 등록, 실제 실행 이력과 결과 수신을 각각 조회한다. 일정만 설정된 상태를 정리 성공으로 보고하지 않는다.

읽기 전용 메타데이터 보고는 로컬 스크립트로 구현할 수 있다. 외부 게시 확인과 의미 기반 기억·스킬 검토는 필요한 계정·내용 접근·호출 비용을 별도 범위로 정한다. 승인된 자동화의 로그와 보고서도 보존 주체·기간을 명시한다.
