# 프로젝트·산출물·기록 관리

## 수행 순서

1. 요청의 승인 범위를 확인한다. 승인용 브리핑 요청은 읽기 전용 조사와 보고서 작성까지 수행하고, 이동·삭제·기억 변경·스킬 변경·예약 등록은 각각 승인받는다.
2. 설치 기록에서 관리 원본과 기존 보존 정책을 찾고 실제 프로젝트 루트·상위 지침을 확인한다. `codex/config/retention.json`처럼 실행기별 정책은 해당 구현에 적용하고 다른 실행기의 설정 범위를 유지한다.
3. 프로젝트·산출물·캐시·날짜별 납품 자료·도구 작업 공간을 메타데이터로 조사한다. 실제 조사 루트와 제외 경로를 기록하고 개인·회사 경계를 유지한다. 파일명 패턴으로 발견한 범위와 전체 디스크 조사를 구분한다.
4. 큰 폴더부터 중간 결과·편집 원본·배포 파일·검증 증거로 분해한다. 진행 중 작업, 중요한 결정, 수동 보호 자료, 미해결 실패와 재생성 근거가 부족한 파일을 보존한다. 후보별로 Git 추적·대응 소스·참조·현재 사용·재생성 경로를 확인한다.
5. 승인 브리핑에 전체 검토 규모, 정확한 대상 경로와 ID, 용량·개수·선정 이유, 보호 대상, 미확인 사항, 격리 위치·기간·복구 조건을 제시한다. 사용자가 일회성 정리와 정기 보고를 독립적으로 승인할 수 있게 분리한다. 실제 조사 결과를 먼저 설명하고 정책 제안은 그 결과에 연결한다.
6. 승인된 실행 직전에 목록과 현재 상태를 대조한다. 사용자가 이전 보호 대상의 삭제를 명시적으로 승인하면 해당 목록에 새 승인과 조건을 반영하고 같은 범위는 재승인 없이 진행한다. 기간 기준은 실행 시각·시간대와 기준 시각을 기록하며, 미래 게시 예외는 정확한 게시 날짜·패키지·실제 참조 파일로 연결한다. 대상이 바뀌거나 승인 범위 밖 보호 조건이 발견되면 해당 대상을 보류한다. 격리 이동은 원래 경로와 복구 정보를 기록하고, 관련 최소 검증에 실패하면 복구한다. 영구 삭제는 별도 승인과 현재 대상 재확인을 거친다.
7. 폴더·파일 합계와 중첩 집계를 검증하고 승인 문서와 근거 목록을 전달한다. 조사, 격리, 삭제, 예약 설치, 실제 실행과 결과 수신을 각각 관찰한 수준으로 보고한다.

## 항상 적용할 기준

- 수정 시각은 후보 선정에 사용하고 실제 마지막 사용 여부는 참조·실행 상태로 확인한다. 인터넷 게시 결과는 실제 게시 상태와 편집 원본 보존 필요성을 확인한 뒤 분류한다.
- 같은 디스크의 격리 이동은 보관 위치 변경으로 보고한다. 논리 용량·할당 용량·실제 회수 공간을 구분하고 회수량은 실행 후 측정한다.
- 스킬은 사용 빈도와 함께 절차 중복·호환성·복구 필요성을 검토한다. 실행기별 동일 사본은 각 실행기의 발견·설치 경계를 유지한다. 설치 관리 스킬은 관리 원본과 설치 절차를 따라 변경한다.
- CodeGraph는 실제 색인 위치와 저장소 연결을 확인한 뒤 재생성 가능한 색인을 후보로 삼는다. 특정 경로의 발견 결과만으로 도구 전체의 색인 상태를 판단하지 않는다.
- GAM은 만료일·임시 태그가 있는 활성 프로젝트 기억을 기존 보호 조건에 따라 보관 처리한다. 중요한 결정·선호·규약·진행 작업·미해결 문제는 보존하고 대체 결정은 연결한다. 색인 상태와 원본 저장소 상태를 구분한다. 사용자 대화와 에이전트 자체 메모리는 별도 승인 범위로 유지한다.
- 자동화의 기본 제안은 로컬 읽기 전용 후보 보고다. 자동 이동·삭제·스킬 변경·기억 변경의 권한은 별도로 지정한다. 성공한 정리에는 식별자·시각·대상·개수·결과만 기록하고 인증값·고객 원문·기억 본문은 포함하지 않는다.

조사 방법·분류표·승인 문서 검증은 [정리 조사와 승인 기준](references/cleanup-audit.md)을 따른다.
