# 한국어 문장 다듬기

## 범위

- 진단 요청: 문제 문장, 유형, 이유를 목록으로 돌려준다. 원문은 고치지 않는다.
- 수정 요청: 필요한 부분만 고친 수정본과 주요 변경 이유를 돌려준다.
- 사실·고유명사·수치·날짜·인용·URL·코드·명령어는 바꾸지 않는다. 글쓴이의 말투(반말·존댓말, 격식)와 문서 장르를 유지한다.
- 같은 글에 영문 구간이 있으면 그 구간은 humanizer 기준으로 따로 본다.

## 찾을 패턴

| 유형 | 예 | 고치는 방향 |
|---|---|---|
| 번역투 어순·조사 | "~에 대해 논의를 진행했다", "~을 통해 ~을 할 수 있다", "~에 있어서" | 동사로 직접: "논의했다", "~으로 ~한다" |
| 과도한 명사화 | "확인 작업을 수행하였다", "개선이 이루어졌다" | "확인했다", "개선했다" |
| 부정·대조 틀 | "단순히 X가 아니라 Y다", "X라기보다는 Y" | 말하려는 Y를 바로 쓴다 |
| 상투적 도입·결론 | "오늘날 빠르게 변화하는 ~에서", "결론적으로", "이를 통해 ~할 수 있을 것입니다" | 삭제하거나 구체적 사실로 바꾼다 |
| 부풀린 수식 | "매우 중요한", "혁신적인", "획기적으로", "다양한" | 근거가 있는 구체 표현이나 수치로 바꾸거나 삭제 |
| 반복 종결 | 문장마다 "~합니다", "~입니다", "~할 수 있습니다" | 문장 길이와 종결을 섞고, 가능성 표현은 사실이면 단정 |
| 기계적 나열 | "첫째, 둘째, 셋째", 모든 문단이 같은 구조 | 내용에 맞게 문단을 합치거나 목록으로 |
| 불필요한 영어 | "인사이트를 리뷰하고 액션 아이템을 디벨롭" | 통용되는 한국어로. 고유명사·코드·업계 표준 용어는 유지 |
| 빈 강조·면책 | "참고로", "물론", "중요한 점은", 요청하지 않은 주의 문구 | 삭제 |
| 이중 피동 | "되어지다", "보여지다" | "되다", "보이다" |

## 순서

1. 독자와 목적(보고, 안내, 기술 문서, 대화)을 정한다. 보고서 문체처럼 프로젝트가 정한 기준이 있으면 그 기준을 먼저 따른다.
2. 위 패턴을 문단 단위로 찾는다. 같은 문제가 반복되면 대표 예와 개수로 묶는다.
3. 수정 요청이면 고친 뒤 원문과 비교해 사실·수치·고유명사가 그대로인지 확인한다.
4. 고칠 것이 없으면 그렇다고 짧게 답한다. 고칠 거리를 만들어 내지 않는다.
