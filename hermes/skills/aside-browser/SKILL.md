# Aside 브라우저 조작

브라우저 작업은 Aside에서 한다. 에이전트가 동작을 정하고 `aside repl`(또는 `repl` 도구만 노출한 Aside MCP)로 JavaScript를 실행해 직접 조작한다. Aside 자체 AI(`aside exec`, 자연어 `aside` 명령, 에이전트 위임 도구)는 사용하지 않는다. `repl`이 실패하면 연결·프로필·호출 코드를 진단해 `repl`로 복구하고, 다른 브라우저나 자체 AI로 바꾸지 않는다.

REPL의 `page`·`openTab` API는 Playwright 문법을 따르는 Aside 자체 경량 엔진(CDP 래퍼)이다. 뷰포트 변경이나 일부 키보드·마우스 함수처럼 없는 함수는 엔진 범위 차이로 보고, Playwright 스크립트를 옮기기 전에 객체의 함수 목록을 한 번 출력해 확인한다. 구독·호환성 설명은 현재 공식 문서와 실제 앱·CLI 동작을 근거로 한다.

## 시작

1. `aside guide repl`과 `aside --help`로 설치된 버전의 REPL 함수를 확인한다. 예전 예시보다 현재 도움말을 따른다. `listBrowserTabs`, `attachBrowserTab`, `openTab`, `snapshot`은 문서화된 함수이고 `getTabs()`는 버전에 따라 없을 수 있다.
2. CLI 하위 명령은 `aside --help`나 guide에서 확인한 것만 쓴다. `aside profile list`처럼 없는 명령은 Aside 자연어 AI로 넘어갈 수 있다.
3. `aside account list`로 계정을 확인한다. 이 목록은 Aside 앱 자체 로그인 계정(u0, u1 …)이고 브라우저 프로필 안의 사이트 로그인과 다른 목록이다. 사이트 로그인 상태는 해당 프로필 탭에서 그 사이트의 계정 메뉴로 확인한다.
4. 프로젝트 지침이 지정한 Aside 프로필을 사용한다. 지정이 없고 작업에 로그인이 필요하면 프로필을 사용자에게 확인한다. 이름이 비슷한 다른 프로필로 대신하지 않는다. 서비스마다 계정이 다른 프로필에 있을 수 있으므로 "회사" 같은 단어는 작업 맥락으로 읽고 서비스별 지정 프로필을 고른다.
5. 지정 프로필 이름이 없거나 바뀌었으면 `~/Library/Application Support/Aside/Local State`의 `profile.info_cache`에서 디렉터리·이름 쌍만 읽는다. 쌍만으로 정할 수 없으면 사용자에게 고르게 한다. 고른 뒤에는 그 프로필 Preferences의 `aside.profile_id`와 일치하는 `profileAccountBindings` 항목의 `accountId`·`profilePath`만 읽어 UUID와 경로를 대조한 뒤 `aside repl --account <id>`를 쓴다. 전체 Preferences·바인딩 파일은 출력하지 않는다.
6. 설치: 앱은 공식 `https://aside.com/api/download/macos`, CLI는 `https://releases.aside.com/install.sh`를 받아 내용을 확인한 뒤 실행한다. 앱은 `hdiutil attach -nobrowse -readonly`로 마운트하고 `codesign --verify --deep --strict`·`spctl --assess --type execute`를 확인한 뒤 복사한다. 다른 브라우저 프로필 가져오기는 desktop-app-provisioning 스킬을 따른다. 앱·CLI 설치, 실행기 연결, 실제 페이지 조작은 각각 확인한다.

## 조작

- 기본 흐름: `openTab(url)` 또는 `listBrowserTabs()`·`attachBrowserTab()` → `snapshot()`으로 상태 읽기 → 클릭·입력 → 다시 읽어 결과 확인.
- 서로 의존하는 동작은 한 번의 `aside repl` 실행 안에 둔다. 한 번 실행한 REPL의 변수와 탭은 다음 실행에서 유지된다고 가정하지 않고, 필요하면 탭을 다시 찾는다. 여러 단계 작업은 대화형 REPL 프로세스 하나를 백그라운드로 띄워 JavaScript를 보내고, 매번 `[ok]`/`[error]` 출력과 snapshot을 읽은 뒤 다음 동작을 정한다. 입력 전달 성공은 실행 결과로 세지 않는다.
- 일회성 `aside repl --account <id>` 호출은 종료할 때 자기 탭을 닫아 진행 중인 요청을 끊는다. 제출 작업은 페이지가 요청 접수(보낸 메시지와 진행 표시)를 보여 줄 때까지 유지하고, 결과 URL을 저장해 나중에 다시 연다.
- 프로세스 종료 코드 0만으로 성공을 판단하지 않는다. 출력에 `[error]`가 있는지 보고, 동작 결과를 다시 읽거나 성공 표시 문자열을 출력해 확인한다.
- 화면 캡처를 파일로 저장했다면 실제 이미지 파일인지 확인한 뒤 보고한다. `page.screenshot({clip})`에 0이 아닌 x/y를 주면 왼쪽 위만 잘린 이미지가 나올 수 있으므로 전체를 저장하고 실제 이미지 크기로 로컬에서 자른다.
- 탭을 만든 사실과 사용자가 그 탭을 화면에서 보는 사실은 별개다. 확인하지 않았다면 "보실 수 있다"고 말하지 않는다. 탭 정리는 관찰한 위치·세션 소유로 후보를 나누고, `active`·제목·URL은 부분 근거로만 쓴다. 사용자 탭은 보존한다.
- `closeTab`에는 `openTab`이 돌려준 page 객체를 넘긴다. 팝업이 생기거나 닫히면 `tabs` 순서가 바뀌므로 숫자 인덱스를 들고 다니지 않고, 닫기 전에 그 객체에서 `location.href`를 읽어 대상을 확인한다. 닫힘은 `listBrowserTabs()`로 다시 확인한다.
- 동작이 실패해도 처음 받은 page 객체를 유지하고 실패한 동작만 다시 시도한다. 같은 실패 호출을 그대로 반복하지 말고 상태를 다시 읽은 뒤 방법을 바꾼다. 클릭이 이미 적용됐을 수 있으므로 재시도 전에 결과 상태를 확인한다.
- 페이지에서 오래 걸리는 fetch는 `.then`으로 `window.__x`에 저장하고 짧은 evaluate로 확인한다. `page.evaluate`의 CDP 제한 시간은 긴 요청보다 짧다.
- 콘솔·네트워크 관찰기는 시험할 동작 전에 등록하고 실제 이벤트가 들어오는지 확인한다. 등록 성공만으로 오류가 없었다고 보고하지 않는다.
- 측정이 필요한 반응형·동작·지연 확인, 사이트별 조작 방법, REPL 환경 차이는 [REPL 조작 기록](references/repl-recipes.md), [반응형 뷰포트 QA](references/responsive-viewport-qa.md), [화면 동작 캡처](references/ui-motion-capture.md), [진행 상태 관찰](references/live-progress-observation.md)을 따른다.

## 계정과 데이터

- 계정이 걸린 변경(게시, 결제, 설정 변경, 삭제) 전에는 해당 서비스의 계정 메뉴에서 실제 이메일을 확인한다. 프로필 이름으로 계정을 추정하지 않는다.
- 브라우저 프로필의 계정과 대상 앱의 로그인 계정은 따로 확인한다. 관리자 권한이 필요한 작업은 앱의 계정 정보 화면이나 사용자 확인 API로 실제 역할을 확인하고, 브라우저 동작·직접 API 확인·로컬 시험 계정·운영 동작을 나눠 보고한다.
- 비밀번호·인증 코드·복구 키는 사용자가 직접 입력한다. 로그인 화면 snapshot을 출력할 때 비밀번호 칸 값은 지우고, REPL 변수에 남은 인증 링크·토큰은 사용 후 비운다. 저장된 로그인 선택기는 연결된 이메일 확인까지만 쓰고 로그인은 사용자가 마친다.
- 유료 결제는 사용자가 승인한 경우에도 결제 화면까지만 진행한다. 결제 화면의 수취인·요금제·청구 주기·오늘 금액·갱신 조건을 보고하고, 카드·OTP 입력과 결제 버튼은 사용자가 처리한다. 완료는 판매처의 요금제 화면으로 확인한다.
- 쿠키·비밀번호 DB·계정 파일 내용을 출력하거나 파일로 저장하지 않는다. 관련 없는 고객 기록이 담긴 전체 화면 캡처는 피한다.
- 같은 사이트 자원을 여러 작업이 동시에 수정하지 않는다. 독립 작업은 서로 다른 REPL 세션이나 workstream으로 변수와 탭을 나누고, 같은 계정의 사이트 상태는 공유된다는 점을 고려한다.

## 실행기 연결

- Claude Code·Codex는 설치된 `aside repl` CLI나 연결된 Aside MCP의 `repl` 도구를 쓴다. 오래 이어진 세션에서 도구 목록이 Aside 설정보다 먼저 만들어졌으면 도구 목록을 다시 조회해 `repl` 도구를 찾는다.
- Hermes에서는 설정한 `aside` MCP의 `repl` 도구를 쓰고, 내장 브라우저나 다른 브라우저로 넘어가지 않는다. Agent-setup이 설치한 Aside 연결 장치(bridge)는 프로필·workstream별 Aside 프로세스를 유지하고, `profile`에는 Aside에 보이는 프로필 이름(`Chrome · ` 접두어 제외)을 넣는다. 진단은 다음과 같다.
  - 브라우저 작업을 마치면 직접 연 탭을 닫고, 직접 띄운 `aside repl` 프로세스를 종료한다. 쓰지 않는 컨텍스트(세션 기록에 최근 성공 호출이 없는 bridge의 `aside mcp` 자식, 중복된 bridge 서버 프로세스, 끝난 세션이 남긴 `aside repl` 프로세스)를 발견하면 바로 정리한다. 진행 중인 세션·하위 작업이 쓰는 프로세스만 남긴다.
  - `16 live contexts reached`처럼 컨텍스트가 가득 차면 위 기준으로 정리한다. CLI 프로세스를 정리해도 bridge 자신의 프로세스 안의 풀은 그대로이므로, 오류가 남으면 bridge 서버 프로세스를 재시작하고 새 프로세스가 뜬 뒤 한 번 재시도한다.
  - 정상 탭에서 `page.screenshot`이 반복해서 CDP 시간 초과를 내면 bridge 서버 프로세스가 중복됐는지 확인하고 하나로 정리한 뒤 재시도한다.
  - bridge를 재시작하기 전에 다른 하위 작업이 같은 프로필을 쓰는지 확인한다. 쓰고 있으면 다른 프로필이나 workstream으로 진행하고, 그 작업이 끝난 뒤 재시작한다.
  - `No browser window is open for account uN`은 프로필 연결과 열린 브라우저 창을 나눠 확인한다. 오류 문구의 프로필 이름과 실제 디렉터리가 다를 수 있으므로 확인한 UUID·경로 바인딩을 유지하고, 창이 열린 뒤 새 탭 열기 → snapshot → 닫기로 복구를 확인한다. 앞으로 띄우기와 공유 프로세스 재시작은 승인을 받는다.

## 보고

이동한 페이지, 수행한 동작, 다시 읽어 확인한 결과를 나눠 적는다. 확인하지 못한 단계는 미확인으로 남긴다. 화면 변경 확인은 실제 컨트롤을 조작하고 캡처를 본 뒤 시험한 폭·스크롤 방향·성공한 동작과 증거 폴더를 짧게 적는다. 포커스·키보드·커서 보존은 읽을 수 있는 활성 앱과 키보드 대상이 있을 때만 확인된 것으로 보고하고, 잠긴 화면에서는 미확인으로 남긴다.
